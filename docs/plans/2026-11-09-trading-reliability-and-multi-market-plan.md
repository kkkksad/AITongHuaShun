# 交易可靠性、策略覆盖与多市场独立资金计划

> 使用 writing-plans 编写、executing-plans 实施。状态：实施中；用户于北京时间2026-11-09晚间明确要求从现在升级到明早08:00。硬截止北京时间2026-11-10 08:00（UTC2026-11-10 00:00），逐模块验证、提交、推送和独立部署。定时续跑kairos已恢复，每20分钟检查；需要电脑与Codex桌面持续可用，已启用到期释放的临时防睡眠。

**Goal:** 让每次未交易都有可追溯原因，消除代码造成的漏单和错误风控，用真实历史检验各市场状态的策略覆盖，再增加资金和规则独立的多市场模拟账户。

**Architecture:** 保留现有A股Paper账户，先加固数据、信号、计划、风控、撮合和复盘链路。行情可共享只读服务，订单必须按账户和市场隔离；期货建立专用合约、保证金、结算、日历和撮合域，不能把A股Broker改名复用。

**Tech Stack:** React / TypeScript / Fastify / Python / AkShare；Vitest / pytest；当前单实例JSON账本，未来按事务需求演进。

- 已上线修复：历史SDK参数错误、复盘输入证据缺失、验证策略重复金额缩放。上一轮117项Linux桥接测试、1672项服务端测试、319项前端测试和构建通过；本轮未重跑这些测试。
- 上一轮收盘后只读计划：12候选、3匹配，修复前0买单，修复后平安银行100股/1189元本金/5元预计买佣金；这只是计划，不是成交或收益。
- 当前有17个可手选的A股执行策略；路由还包含内部风险修复/资金防守策略。存在策略不等于该策略能在实际市场、实际资金下产生有效信号。
- A股已有本地Paper闭环；期货现为16个受控主连的只读研究，没有独立期货资金、保证金、具体合约订单或撮合。港股、数字资产及外盘同样不能从研究页面直接推导为已具备交易能力。
- 现有账户和订单模型以单一A股账户为中心；订单/持仓缺少完整的市场与账户路由字段，当前不能直接同时承载多市场账本。

## 2. 数据是否实时捕获

| 层级 | 当前实际行为 | 对交易的意义 |
| --- | --- | --- |
| A股快照 | 线上`MARKET_TICK_MS=30000`，每轮完成后再等待30秒；来源为AkShare桥接的公开真实/延迟行情 | 不是交易所逐笔推送，不保证30秒内源价格一定更新 |
| 股票/指数桥接 | 10秒缓存；刷新失败保留旧值并退避 | HTTP成功、页面刷新和报价真正新鲜必须分开判断 |
| 自动策略 | 每轮完成后等待60秒，限制在A股日历/时段内 | 慢请求会拉长实际检查间隔，不是整点每分钟必运行 |
| 历史研究 | 桥接15分钟缓存，允许有界旧值后台刷新；后端还存在独立请求/研究缓存 | 日线支持中期结构，不能充当即时可成交报价 |
| 期货研究快照 | 桥接`get_futures_quotes`使用15分钟研究缓存，后端还有60秒请求缓存 | 当前刷新机制仅适合观察，接入撮合前必须独立改造 |
| 数据保存 | 主要是进程内缓存及有界研究记录 | 当前并未完整、长期录制每笔tick；后续只保存必要且有来源版本的紧凑数据 |

新设计必须同时保存来源报价时间、服务接收时间和本次请求完成时间；界面显示数据年龄、市场时段及降级状态。股票和期货分别定义最大可用报价年龄，休市不伪造新报价，过期报价不得用于新成交。

## 6. 子计划C：按市场状态补策略并提升验证质量

| 市场状态 | 先检查的现有策略族 | 确有覆盖缺口时研究的增量 | 禁止混淆 |
| --- | --- | --- | --- |
| 上涨低波动 | 低波趋势、均线、趋势健康 | 相对强度轮动、趋势回踩后确认 | 名字不同但信号高度重复不算覆盖增加 |
| 上涨高波动 | 缩量回踩、洗盘恢复、量价突破 | 带波动约束的突破回踩确认 | 不能通过放宽追高阈值增加交易 |
| 低波震荡 | RSI、布林带、区间轮动 | 区间边界与趋势退出结合 | 破位后不能继续机械摊平 |
| 高波震荡 | 受控区间、安静回踩、合格验证 | 波动归一化反转/回归，先做旁路比较 | 验证篮子成交不等于主策略成功 |
| 风险收缩/下跌 | A股减仓、防守、现金 | 期货账户将来可验证空头趋势 | A股账户不因此获得做空或期货权限 |
| 风险修复 | 风险修复观察、趋势/广度重新确认 | 连续确认和切换滞回 | 单日反弹不等于修复完成 |
| 数据不足/状态不明 | 数据恢复与观察 | 改善数据和可解释性 | 不增加“任何时候都买”的兜底策略 |

相关现有文件：`adaptiveStrategyRouter.ts`、`adaptiveCandidateStrategy.ts`、`strategyRobustness.ts`、`server/backtest/`、`server/strategies/`、`server/optimizer/`。

- [ ] 先建立状态×策略覆盖矩阵，分别统计有资格、真信号、可买金额、可成交数量；确定是没有策略、信号条件错误、信号过严还是数据不支持，不能凭0成交直接增加策略。
- [ ] 逐策略核对指标暖机、参数边界、复权、成交量单位、单标的隔离、未来数据、日线未收盘、信号时间与下单时间、买卖实际持仓状态。
- [ ] 使用版本化真实历史、当时可见股票池、时间隔离滚动验证；现有合成排行榜继续明确标为演示，不能用来证明新增策略有效。
- [ ] 同时报告胜率、平均盈利/亏损、净期望、盈利因子、最大回撤、换手、暴露时长、成交数、费用后收益及置信区间；少于30个闭合交易对只做探索性展示，达到该数也不视为效果已证明。

- [ ] 只有新增策略有独立增量证据，才进入候选旁路 → Paper观察 → 有限正式Paper额度；退化先降权/停用，不自动放松风险线。

**交付：** 状态覆盖矩阵、真实样本外对照报告、明确通过/未通过结论；不能承诺某个胜率或每日最低成交数。

## 7. 子计划D：股票、期货等独立资金并行模拟交易

### 7.1 账户与规则隔离

| 账户 | 本金 | 规则与账本 |
| --- | --- | --- |
| 现有A股Paper | 保留当前20000元与已有状态 | 100股整手、T+1、股票费用、自己的持仓/订单/熔断 |
| 新期货Paper | 另设本金，具体数额由用户配置 | 合约乘数/最小跳动、手数、开平仓、多空、保证金、结算、独立损益与熔断 |
| 后续港股等 | 各自另设本金 | 按该市场货币、每手股数、费用、交易日历和订单语义实现 |

账户之间不自动划款、不共用可用资金、持仓、冻结额、订单额度、幂等空间或亏损止损线。总览只汇总，单市场暂停可以独立生效；全局紧急停止仍可同时关闭各市场新增。期货保证金是必要履约资金，不能按取消股票固定现金预留的决定删除。

### 7.2 多市场基础层

先设计新共享契约：账户标识、市场、币种、具体可交易品种、交易日、规则版本；所有订单/持仓/成交/审计/资金流水/幂等键绑定账户。当前 `shared/trading.ts` 与 `TradingSystem` 不能直接扩成无隔离的共享对象。

- [ ] 制定迁移ADR：备份、旧A股账本原样导入、迁移可重入、迁移失败回滚、旧客户端兼容；不得借新增账户清空原账户。
- [ ] 为各账户实例化独立Store、Broker、Risk与Scheduler；任何接口按登录权限和账户白名单路由，错误账户或错误市场在写盘前拒绝。
- [ ] 资金变更使用可核对流水和原子提交；先验证现有单实例分账方案，交易并发或结算需求超过JSON能力时再迁移事务数据库，不能多进程共享单文件写账。
- [ ] 交叉污染测试：相同clientOrderId不同账户、相同symbol不同市场、重置/暂停/撤单/重启、费用/保证金冻结、串错账户参数都必须保持资金独立。

### 7.3 期货交易前置条件

相关现有文件：`server/research/crossMarketStrategyContext.ts`、`src/components/FuturesMarketPanel.tsx`、`akshare-bridge/main.py`；新增期货交易域必须单独设计并测试，不把主连研究模块改成订单入口。

- [ ] 明确公开数据的可用范围和延迟；将交易报价从15分钟研究缓存中分离，检查来源时间与新鲜度。拿不到合格具体合约报价时继续只读。
- [ ] 主连仅用于研究，建立主连到当期具体合约的可追溯映射；记录换月和到期，禁止把连续主连当成可交易合约直接撮合或计算真实可实现损益。
- [ ] 维护有来源、时间与版本的合约乘数、tick、保证金率、费用、平今/平昨、涨跌停、交割限制；支持不同交易所和品种，不套用股票100股与T+1。
- [ ] 支持多/空、开仓/平仓、冻结/释放保证金、浮盈亏、逐日盯市、结算与资金不足处理；低保证金占用不等于低名义风险。
- [ ] 独立夜盘/日盘/节假日和交易日归属；跨午夜仍可属于同一交易日，不能照搬A股北京时间日期键。
- [ ] 首批只选择少量有完整数据和合约规则的流动品种，验证趋势突破、趋势回踩与受控区间策略；费用、保证金、止损与极端情形全部通过后才开启该账户模拟撮合。

**交付：** 账户隔离和迁移报告、期货规则/报价验收、确定性撮合与结算测试、独立资金总览。先实现股票+期货；其他市场在此基础上逐个接入，不为每个展示模块创建交易资金。新闻、全球影响、玄学等研究域继续没有订单权限。
