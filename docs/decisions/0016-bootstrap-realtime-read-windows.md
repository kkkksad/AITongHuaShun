# 0016：初始化读取合并已接收的实时事件

- 状态：接受
- 日期：2026-11-05

## 背景

浏览器的REST初始化读取与WebSocket同时开始。未有缓存时早到的推送原先被丢弃，已有缓存的手动刷新也可能被迟到GET覆盖成旧账户、持仓或订单。反复因行情取消GET会造成初始化无法完成。

## 决策

1. 初始化和手动刷新共用一个读取函数。每个读取窗口压缩保存收到的市场、账户、持仓和订单更新，完成REST后合并该窗口内事件；初次失败保留尚未落地的事件，成功后消费覆盖层，让后续无新事件的REST正常前进。
2. 订单完整快照最多50笔。缺完整快照时，增量记录按ID去重并保留最多100次ID操作以维持原upsert顺序；溢出后仅补读一次受保护的最近50笔订单，并合并补读期间的更新。失败或再次溢出明确提示列表可能不完整，不无限抓取或伪装完成。
3. 生命周期epoch与当前socket身份共同保护结果。禁用、卸载或重置成功同步失效旧epoch、取消旧读取；旧socket即使尚未完成React清理也不能再写当前数据。忽略AbortSignal的迟到请求仍由身份门阻止，取消不是网络故障。
4. 维持既有认证、Cookie、CSRF和后端权限；新增订单补读只复用已有只读API，不新增下单或重置操作。

## 结果与代价

持续行情不再导致初始化饥饿，客户端已收到的更新不会仅因本轮GET较晚完成而丢失。状态与缓冲都有固定上限。此机制不提供服务端统一版本，也不声称REST多个端点与WebSocket具有绝对全序或原子快照；要获得更强保证需要独立的服务端版本协议。

## 被取代关系

取代初始化为空时丢弃推送、刷新整体覆盖实时数据的客户端方式；保留既有订单上限、增量upsert、重连退避和认证边界。
