# 0058：实时客户端传输故障不传播到交易回调

日期：2026-11-11；状态：接受。被取代关系：无。

## 背景

WebSocketHub原先直接调用socket.send/ping/terminate。一个客户端的同步传输异常可以中断后续广播；真实Fastify/行情/Broker接线证明会打断行情回调中的markToMarket，或在模拟订单已写入后中断回执处理。重复add也会遗留旧心跳。七项受控新增回归旧版失败，不能据此声称今日生产已经发生这些异常。

另查明isAlive/pruneStale在生产没有外部调用，90秒无pong的清理只有定义、没有实际调度；补充实际时间推进回归先失败。

## 决策

send只捕获socket传输调用异常，先移除该连接及其心跳，再尽力terminate。坏连接不打断其他连接或业务调用；ping及手动prune中的terminate同样隔离。重复add幂等，close/error沿用原清理。JSON事件编码在try之外，应用编码错误继续显式抛出，不把服务端错误伪装为断连。

现有30秒心跳每次先检查最后pong，达到90秒即清理，正常pong继续延长活跃期；不增加第二个调度器。手动prune仍可使用，单个终止异常不能阻断其他清理。

## 结果与代价

目标四文件28项通过，包含真实Fastify两客户端和交易系统：注入一个socket发送异常后，正常客户端继续收到行情/订单、markToMarket继续、模拟订单保持实际filled，健康接口可读。心跳超时、pong、异常终止、重复注册和服务端编码错误分别验证。测试均隔离于生产账户和网络通知。

该变化不重试任何订单、不恢复/制造成交，也不修改策略、行情资格、资金或费用。传输故障仍会使该浏览器连接断开，需要正常重连获取快照；不是可靠消息队列或历史事件重放。没有新增worker或提高并发。完整验证与实际发布见[持续计划](../plans/2026-11-10-overnight-strategy-and-loading.md)。
