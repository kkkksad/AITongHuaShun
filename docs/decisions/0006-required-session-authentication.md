# 0006：强制服务端会话认证

**状态：** 接受
**日期：** 2026-07-14

## 背景

0005 建立了可选本地 JWT 原型，但令牌保存在 `localStorage` 并进入 WebSocket URL，环境变量保存明文密码，登出无法在服务端撤销令牌，且能力声明、指标和 API 文档仍可匿名访问。这些约束不适合计划中的公网服务器部署。

## 决策

- 正常运行默认强制认证；`AUTH_ENABLED=false` 只允许 `NODE_ENV=test`。
- 服务端只接受 `AUTH_PASSWORD_HASH` 中固定参数的 Node.js `scrypt` 散列，不接受明文密码配置，不提供默认账号或默认密码。
- 登录创建 256 位随机、不透明会话令牌；服务端只保存令牌 SHA-256 摘要、用户、角色、CSRF 值和过期时间。
- 浏览器会话只使用 `HttpOnly`、`SameSite=Strict`、`Path=/` Cookie；生产环境必须启用 `Secure` 并通过 HTTPS 访问。
- 服务端登出立即撤销会话；会话有 TTL 和单用户数量上限。当前内存实现仅允许单后端实例，服务重启主动使所有会话失效。
- 除最小健康检查、登录、会话检查和由握手处理器自行验证的 WebSocket 外，业务 API、能力声明、指标和 OpenAPI 文档统一经过认证钩子。
- 所有非安全方法同时校验会话级 `X-CSRF-Token`；登录使用独立低频限流，全局 HTTP 限流继续保留。
- WebSocket 只读取 Cookie 并验证 `Origin`，不接受查询参数令牌。前端不在 `localStorage`、`sessionStorage` 或 URL 保存认证材料。
- 此认证只保护研究与模拟交易工作台，不授权真实券商执行。真实资金仍需要独立身份域、账户白名单、逐笔批准和独立执行网关。

## 结果

优点：认证默认失败关闭；XSS 无法直接读取会话 Cookie；代理日志与浏览器历史不再包含令牌；登出和会话上限可由服务端执行；部署配置缺失时拒绝启动。

代价：服务重启需要重新登录；当前不能运行多个后端副本；本地 HTTP 必须显式使用非安全 Cookie 配置；公网部署必须增加 HTTPS 反向代理和外层限流。
