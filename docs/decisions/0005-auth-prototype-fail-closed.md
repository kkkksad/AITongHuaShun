# 0005：认证原型默认禁用与显式配置

**状态：** 接受  
**日期：** 2026-07-11

## 背景

仓库新增了本地 JWT 认证原型，但项目尚未完成身份提供商、用户存储、密码散列、角色权限、会话撤销、账户白名单和审批服务。硬编码默认管理员账号或签名密钥会让误注册的认证路由产生虚假的安全感，并可能暴露模拟交易 API。

## 决策

- 认证原型不提供默认用户名、密码或 JWT 密钥。
- 注册认证路由前必须显式提供用户名、至少 12 字符的密码、至少 32 字符的随机签名密钥和短期令牌时长。
- 缺少或弱化配置时，认证路由注册必须失败。
- HMAC 签名和凭据比较使用固定长度摘要与恒定时间比较。
- 令牌验证必须检查算法、类型、载荷结构、签发时间和过期时间。
- 当前 `buildTradingApp` 不注册认证路由；文档必须继续声明 API 尚未受用户认证保护。
- 真实交易不得使用浏览器 `localStorage` 保存令牌，必须采用独立身份域、受保护会话、角色授权和逐笔审批。

## 结果

优点：

- 删除了可被误用的默认管理员账号和默认签名密钥。
- 未配置环境不会悄悄退化为不安全认证。
- 认证逻辑可以独立测试，而不影响当前模拟交易开发流程。
- 为后续身份提供商和权限系统保留明确替换边界。

代价：

- 当前 API 仍未启用认证，不能把原型存在误解为接口已受保护。
- 环境变量中的明文本地密码只适合开发验证，生产环境仍需密码散列或外部身份提供商。
- 令牌撤销、刷新、会话管理、多用户和角色策略仍未实现。
