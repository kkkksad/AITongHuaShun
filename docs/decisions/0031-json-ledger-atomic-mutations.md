# 0031：JSON账本单次变更统一提交与失败回退

- 状态：接受，实现完成、验证/发布中。
- 日期：2026-11-10（北京时间）。
- 被取代关系：完善原单进程JSON文件仓储，不迁移主账本至SQLite或更改账户世代。

## 背景

故障注入复现了文件替换失败时内存现金、持仓、订单、冻结和审计已改变；以后一次成功写入可能将原本失败的操作带入文件。下单、成交、撤单、拒单、暂停、策略切换与重置还因`appendAudit`和外层`flush`各写一次，产生重复文件替换；失败若发生在第二次替换，调用者看见异常而第一次已经提交。

## 决策

所有公开JSON变更进入同一同步`mutate`范围，捕获资金、持仓/周期、订单、审计、序列、档位、暂停、账户世代和风险检查点。内部嵌套审计只请求保存，最外层成功结束才执行一次临时文件写入和原子替换。没有任何实际保存请求的终态幂等操作不重写文件。

若变更或替换失败，恢复本次操作前的全部内存字段，文件保留之前版本；后续成功操作不能带入失败的订单、成交、冻结释放、重置或审计。风险检查点保存使用同一范围，失败时getter仍返回旧检查点。Broker事件在Store返回成功后发送，避免向外宣称未提交的成交。

## 结果与代价

九类公开变更实测每次一次文件替换，替换前抛错时全部回退；独立旧HEAD对照19项中17失败，修复后全部通过。另有真实临时路径写入失败、成交结果不被后续保存带入的回归。

每次变更复制有界周期结果及当前订单/审计状态，增加少量内存复制；当前单账户、有限历史、每日硬上限场景下用于换取一致性，不承诺高频/多实例性能。文件替换仍不提供多进程锁、数据库隔离或断电fsync持久性，独立归档也不是执行数据库。初始化和旧文件迁移不是用户变更流程；保留其启动失败语义。实际生产只读核验，不主动制造磁盘故障或重置账户。
