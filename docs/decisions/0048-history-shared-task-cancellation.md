# 0048：历史缓存共享读取不属于单个等待者

日期：2026-11-10（北京时间）。状态：已实现，发布事实见[模块28](../plans/2026-11-10-history-caller-cancellation.md)。

## 背景

ResearchHistoryCache冷读直接await共享Task。一个调用方取消或wait_for超时会取消该Task，其他等待者一起收到CancelledError；HistoryFetchLimiter同时释放名额，但run_in_executor线程可能仍在工作，后续请求还能重复启动同一来源读取。五类新增回归在旧实现全部失败，真实线程案例确认active提前降为0。

这是内部共享缓存API的所有权缺陷，不表示当前REST断开必然会取消主桥接fetch_one；现有批次asyncio.wait本来就不主动取消子任务。

## 决定

冷读仅使用asyncio.shield等待共享任务。取消/期限只作用于本调用，原任务保留缓存引用和调度名额至实际封装读取结束；其他调用得到原结果或来源失败。全部等待者退出后仍可完成预热，失败不缓存为成功且可重试。

不新增队列、线程、定时器、上游请求或重试；不改变来源时间、TTL、策略/订单和2工作槽/24接纳。显式clear仍遵循原取消行为，本模块不保证clear能停止底层线程；来源网络期限继续负责底层退出，不能把shield解释为取消了底层任务。

## 验证与限制

五类覆盖首个调用取消、调用方超时、来源错误与重试、真实executor的active/排队/超额拒绝、全部等待者退出仍预热。原166项保持、Linux完整171项通过；实际镜像与应用完整回归事实统一写入模块28计划。未测试或改变生产HTTP客户端断开的服务器取消策略，不以隔离线程实验替代线上容量测量。
