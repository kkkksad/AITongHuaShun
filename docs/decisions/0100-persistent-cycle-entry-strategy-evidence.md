# 0100：持久化实际成交周期的入场策略证据

日期：2026-11-13（北京时间）。状态：已实现，验证与部署接续[计划](../plans/2026-11-12-persistent-entry-strategy-evidence.md)。

## 问题与边界

服务端订单记录strategyKey，但持仓周期只保留openingOrderId与现金流。长持仓的订单被正常裁剪后，不能可靠归属入场策略，更不能用当前执行选项推断旧仓来源。现有通用退出不依赖该字段；本项补证据，不改变退出条件、资金、数量、费用或风险许可。

## 方案

OpenPaperPositionCycle新增可选entryStrategyEvidence：single携带共享有限Paper策略键，mixed表示已知买入来源不同，unknown表示至少有买入来源无法确认。旧字段缺失同样为未知。只在实际买单成交时读取已存服务端OrderRecord，拒单/撤单不记；挂单延后成交继续使用原订单来源，不使用当前策略选择。只认PAPER_EXECUTION_STRATEGY_KEYS中的具体键，auto、名称文案及任意外部字符串不作具体身份。

新周期按首次实际买入生成证据，同策略加仓保留；不同已知策略加仓转mixed；任一未知买入使整周期unknown，之后的已知加仓不能修复。旧周期缺字段即便还保留开仓订单也不自动回填；只有实际发生新买入时才记录其仍未知。缺失整个入场现金流的旧持仓不因加仓变成完整周期。

部分卖出保留买入归属，卖出策略不能覆盖它；实际清仓后新买入才开启独立归属。完整闭合周期保留证据并延续原512结果上限。未知优先于混合，状态不是收益、置信度或未来许可。

新增字段严格验证：single必须且只能包含状态/合法键，mixed/unknown只能含状态；非法显式字段在JSON裁剪/回写前拒绝。missing-entry闭合不得声称入场归属。副本读取、入账追加和JSON原子失败恢复独立复制嵌套证据。沿用version=1的可选追加兼容，不执行load-time迁移；今后删除合法策略键须先另定历史兼容政策，不能顺手改白名单破坏持久数据。

同周期另存entryStrategyBoughtQuantity，必须与累计boughtQuantity严格相同，与entryStrategyEvidence成对出现。旧版本买入若保留旧证据却未更新覆盖数量，恢复本版本时拒绝这类过期归属，不能把它继续当可信single；旧版本只卖出不改变累计买入时原覆盖仍有效。没有字段的旧周期继续接受为未知，不能用该数量校验自动猜测或修补归属。

该字段目前是内部账本证据，尚无页面卡片、开放持仓查询或生产分策略退出。独立固定策略回测没有可核实服务端来源时仍unknown，不能把策略类名默写成真实下单来源。
