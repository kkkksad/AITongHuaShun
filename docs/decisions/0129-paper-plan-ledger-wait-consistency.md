# 0129：Paper计划研究等待前后的本地账本一致性

日期：2026-11-13。状态：本地实现和验证完成，发布状态见[执行计划](../plans/2026-11-13-paper-plan-ledger-consistency.md)。

## 问题

buildCurrentPaperTradingPlan在历史研究前获取账户和持仓，在等待后才列出订单。普通成交、挂单、撤单和拒单不会推进账户控制修订号，原有控制修订检查无法识别这类变化，计划会混用两个时点的现金、持仓与订单。

## 决策

首次await前保留最近10000笔订单的独立平面副本、全部现存pending订单的独立平面副本、总现金和可用现金。研究完成或降级后先执行原账户控制检查，再以数值和精确结构比较这些证据；任一变化抛PaperExecutionContextChangedError的ledger固定理由。HTTP复用认证后的409/no-store，执行器复用watch-only处理，不通知或自动提交过期计划。

正常计划使用冻结的orders，不再次混入晚到订单。全部pending独立比较，覆盖最近10000笔之外的旧挂单；必须复制可变订单记录，不能只比较数量、现金或保留原引用。精确比较使用Node内置isDeepStrictEqual，不新增依赖、网络读取、持久字段、重试或自动撤单。

## 验证及边界

真实PaperBroker和内存/JSON两Store复现挂单、成交、撤单、拒单及资金恢复的变化；实际10000笔窗口之外的卖单撤销/成交也覆盖。旧版有效案例24失败/2正常控制，修复后新增26项与相关合计111项通过；完整200文件3420后端、server/app TypeScript和Vite通过。首轮未等待研究启动的无效测试夹具已修正，不作产品缺陷证据。

24组冻结时钟的完整旧/新服务结果及经济输入保持，外部读取为0。单独订单复制/比较CPU中位数6笔约0.0031ms、10000笔约3.47ms（各21次），不是生产延迟或提速结论。正常报价、审计和风险观察变化不独立作废计划。
