# 0055：遗传参数搜索的协作调度

日期：2026-11-11；状态：接受。被取代关系：无。

## 背景

网格搜索已有单调时钟切片，遗传搜索仍只在工厂返回的Promise处等待。同步或立即完成的工厂会连续运行微任务，定时器和网络事件可能一直等到整次搜索结束。真实定时器配合受控CPU工厂的正常/全部失败两项回归在旧版均失败。遗传搜索目前是独立公开优化库，当前合成排行榜使用网格路径；本问题不是已证实的线上交易阻塞根因。

## 决策

每次遗传搜索独立记录performance.now起点，在每个个体评估后（包括缓存命中、失败）以及每对子代繁殖后检查累计切片。达到8ms时通过node:timers/promises.setImmediate让出宏任务，返回后重新计时。

不改变随机种子和随机调用次序、参数、缓存去重、试验编号、费用后指标、目标评分、排序、best或收敛曲线。一次同步工厂、回测、初始化或排序不可抢占，因此8ms是检查门槛，不是响应时间硬上限；没有新增worker、并发、网络请求或交易许可。

## 结果与代价

正常和全部失败的真实定时器回归修复，同种子重复结果保持。另用修改前版本与当前版本逐项比较正常、全部失败、负收益加Sharpe三个目标场景，剥离耗时后所有试验、指标、顺序和收敛相同。总计算量没有减少，频繁让出存在少量调度开销；不能据此声称生产P95或胜率改善。完整验证和实际发布见[持续计划](../plans/2026-11-10-overnight-strategy-and-loading.md)。
