# 0088：API监控区分最近耗时样本与累计计数

**日期：** 2026-11-12（北京时间）

**状态：** 已实现；验证与部署见[执行计划](../plans/2026-11-11-performance-monitor-sample-scope.md)。

## 问题与决策

页面把所有指标称为最近有限样本，但既有合同只对P50/P95使用每条保留路由最近的有限耗时样本；请求、失败、慢请求、平均与最高耗时使用该路由累计记录。旧失败或高耗时离开采样环后仍进入累计值，这不是固定时间窗口。

保留所有计算、采样上限、轮询和响应合同，只修改摘要、表头、范围说明和后端建议固定文案。累计仅覆盖当前进程中仍保留的路由；重启或路由淘汰会清除对应累计值。默认最多64路由、每路由128耗时样本，页面读取响应实际上限。

## 验证与限制

真实RequestTelemetry输入五次请求、仅保留最近两次耗时：累计五次/一次失败/平均412ms，最近P95为20ms；页面明确不同范围。新增回归旧版失败，最终前端400项、后端监控八项及TS/Vite通过。六组隔离Chrome覆盖390/479/1440宽度与有样本/空样本，零HTTP请求且无页面横溢，390截图人工检查通过。

这项说明修复不增加性能采样、不改变交易与账户，也不能称为加载提速。
