# 0001：将代码仓库作为记录系统

**状态：** 接受
**日期：** 2026-07-11

## 背景

单个大型 `AGENTS.md` 会占用上下文、混合不同主题、快速过期，并且难以检查覆盖率、所有权、链接和新鲜度。

## 决策

- 将 `AGENTS.md` 控制为简短的导航地图，保存项目目标、硬约束、任务路由和通用流程。
- 将详细知识放入结构化的 `docs/` 目录。
- 为每个主题指定一个权威文档，其他位置只链接，不复制。
- 将当前事实、目标设计、实施计划和长期决策分开记录。
- 代码或配置改变事实时，同一项工作必须更新对应文档。

## 结果

优点：

- 智能体可以按任务选择性加载上下文。
- 文档更容易审查、链接、更新和机械检查。
- 过期内容的责任边界更清晰。

代价：

- 新增文档时必须选择正确归属。
- 维护者需要同步更新索引和交叉链接。
- 重复信息必须主动合并到单一权威来源。
