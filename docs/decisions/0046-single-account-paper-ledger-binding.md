# 0046：单账户Paper账本必须匹配存储身份

日期：2026-11-10（北京时间）。状态：已实现，发布验收见[模块26](../plans/2026-11-10-paper-ledger-account-binding.md)。

## 背景

两个Store当前固定PAPER-CN-01，JSON保存accountId却在load中忽略它。放错文件后会载入其他账户的资金与订单；缺世代或历史裁剪还会用当前Store身份保存该文件。多市场扩展前必须先封住这条现有单账户边界，不靠不同目录名称隐式证明账户正确。

## 决定

- JsonFileTradingStore版本检查后立即严格验证持久accountId等于Store身份，先于载入资金/订单/风险、历史裁剪和旧世代迁移。
- 错误、空值、缺失或类型不符均以固定错误拒绝启动，不输出输入值、不猜身份、不创建/重置账户、不修改原文件。
- 正确PAPER-CN-01保留既有无epoch迁移、预约资金和账户控制兼容行为；构造参数startingCash不能覆盖既有资金。
- 本模块不接受任意accountId配置，不创建多账户或期货执行权限。多市场仍需账户/市场/币种/规则版本和资金/幂等/风控的显式隔离。

## 验证与代价

真实Store文件构造九类错误身份（含期货、其他股票账户、格式/类型与缺失），旧版九项均未拒绝；正常载入控制项通过。修复后目标身份/原子/世代/执行边界四文件63项通过，验证失败文件字节与目录内容保持、正确账户资金及挂单保持。完整测试与实际发布事实记录在模块26计划。

历史version1合同本来要求accountId；身份缺失文件现在需要依据可信备份核对后恢复，服务不会为继续运行自行认领这份账本。该保护不是数据库事务隔离或多进程锁。
