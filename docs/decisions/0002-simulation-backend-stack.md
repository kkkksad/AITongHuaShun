# 0002：采用 TypeScript 模拟交易后端栈

**状态：** 接受  
**日期：** 2026-07-11

## 背景

前端原型需要从静态账户展示演进为可验证的模拟交易闭环，同时为未来真实数据、持久化和券商沙箱保留清晰边界。当前阶段不需要微服务集群，也不能引入任何真实下单能力。

## 决策

- 使用 Fastify + TypeScript 提供本地 REST API。
- 使用 `@fastify/websocket` 推送行情、账户、持仓和订单事件。
- 使用 Zod 校验环境变量和外部请求。
- 使用 Vitest 统一测试回测、风险、撮合和 API。
- 使用内存仓储保存当前模拟会话，明确不承诺重启后持久化。
- 使用 `PaperBroker` 作为唯一订单执行实现。
- 对 `MARKET_MODE=live` 采用启动时拒绝，不提供空壳实盘适配器。
- 前后端通过 `shared/trading.ts` 共享稳定契约。

## 结果

优点：

- 前后端使用同一种语言和类型系统，适合当前单仓库快速验证。
- Fastify 插件和模块边界便于后续替换数据、仓储与认证实现。
- 模拟撮合、风险和 HTTP 层可以分别测试。
- WebSocket 与 REST 分工明确，页面可实时更新且可重新拉取快照。
- 默认不存在真实交易代码，降低误配置风险。

代价：

- 内存仓储不适合多实例、恢复、合规审计或长期运行。
- 当前事件总线只在单进程内工作。
- 真实数据接入前仍需定义供应商无关的 Provider 契约。
- 进入真实交易评估前必须新增数据库、认证、密钥管理、审批、持久化事件和独立执行权限域。
