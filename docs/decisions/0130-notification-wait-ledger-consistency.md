# 0130：Paper执行器通知等待后复核账本

日期：2026-11-13。状态：本地实现与验证完成，发布结果见[计划](../plans/2026-11-13-executor-notification-ledger-consistency.md)。

## 问题

0129保护计划内部的历史研究等待，但执行器在预检后还可能等待notify网络操作。期间普通挂单、成交、撤单或拒单不推进控制修订号；旧执行器返回后会继续使用准备好的订单。真实本地反例观察到它确实提交了自动买单，不只是页面标记仍为actionable。

## 决策

将0129的最近10000笔订单、全部pending平面副本、总/可用现金捕获与精确比较抽成paperExecutionContext的capturePaperLedgerContext/assertPaperLedgerContext。计划服务仍在原位置使用，正常使用冻结orders。

执行器在原notify await前按需捕获，返回先执行原控制检查，再复核账本；变化沿原PaperExecutionContextChangedError转watch-only，保留外部成功操作，不提交这份过期计划或发送其成交回执。不提供自动重试，也不能撤回已发送计划通知。

无通知时不新增捕获；在已有日期/时段早退之后捕获，保留不提前读取执行订单历史的控制。比较不进入本轮同步提交循环，不把自己的第一笔成交当作异常变化而阻止第二笔。

## 验证与范围

两种真实Store及Broker的通知等待18项中，旧版14反例失败、4控制通过；修复后163相关、完整201文件3438后端、server/app TS/Vite通过。原0129的实际10000笔外旧挂单测试随共享函数继续通过；24组完整旧/新服务输出及经济输入保持、外部读取0。这是等价回归，不是新的策略样本外检验或收益证据。

普通价格变化（不穿越既有挂单价格）、审计及风险观察不导致冲突；不变账本下自己的两笔成交仍完成。初版在研究前额外捕获破坏四项日期/时段早退的无订单读取控制，现收窄到通知前并全部恢复。

本项不覆盖研究返回包装微任务间隙、onOrder或其他同步事件回调的全部并发、所有其他计划消费者或跨进程事务。不声称真实账户发生过此问题，不改变策略、仓位、费用、整手、T+1、零固定预留或硬限额。
