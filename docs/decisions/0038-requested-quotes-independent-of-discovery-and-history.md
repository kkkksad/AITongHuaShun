# 0038：指定行情独立于全市场发现与历史研究

- 状态：接受（模块17B，发布核验见计划）
- 日期：2026-11-10（北京时间）
- 关联：[0037来源时间](0037-quote-source-time-is-not-fetch-time.md)、[模块17](../plans/2026-11-10-quote-time-and-requested-polling.md)。

## 背景

全市场东方财富源实际抓取5927行约63秒，且不含报价来源时间。原个股/指数轮询与历史研究共享AkShare执行槽；即使观察池只有十余只，仍等待全市场刷新。增加历史并发或CPU上限不能直接消除此类上游网络等待。

## 决策

1. 个股行情仅读取本次合法六位代码；指数限定现有受控白名单，使用腾讯公开只读文本源，保留每个价格自己的来源时间。响应明确`source=tencent-quote-text`与部分缺失警告，不拼接其他来源时间。
2. 股票/指数各有独立逐标的TTL/LRU缓存，分别最多256/32个条目，股票单批最多100只，指数仍受四个受控代码限制；正/负缓存共用容量。成功从完成时开始10秒TTL，失败/缺失冷却20秒。旧报价只保留原时间，不因重试被刷新。
3. 每缓存最多一批在途，共用两个独立行情工作线程。相同/重叠请求共享在途，异批繁忙直接返回已有结果并记录deferred，不设置待执行队列；冷读最多等待6秒，任务继续后台完成。调用取消或超时不能提前释放抓取槽，避免底层线程尚在运行就重复提交。
4. 历史研究和全市场搜索仍使用原有AkShare执行槽；HTTP服务就绪不等待上游。名称搜索按需启动单个后台预热、立即返回已缓存匹配，冷启动明确提示预热，避免首个搜索同步等待全市场一分钟。
5. `/health`仅输出有界缓存数量、活跃数、批次数、缺失/失败/延后/淘汰计数，不输出供应商错误正文或凭据。腾讯数值非有限时按缺失处理；零成交量报价保留观察但不可交易。

## 结果与代价

交易观察池不再为了全市场发现或历史抓取排队。受控测试证明占满两个历史线程时指定报价仍能完成；这不是生产容量测量。单源不可用时保留旧来源时间或缺失，不能降为无时间源假装实时。繁忙且无缓存的不同请求可能暂时拿不到报价，下一轮重试；首次名称搜索可能需要等待后台完整扫描，界面应按警告解释。

公开源报价仍可能延迟，休市来源时间仍是历史时点。Broker120秒/5秒门槛、模拟资金、策略资格和真实执行关闭保持，不保证交易次数或胜率。
