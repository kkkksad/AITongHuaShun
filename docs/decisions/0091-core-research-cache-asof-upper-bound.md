# 0091：核心研究缓存不得向较早请求提供较晚上下文

**日期：** 2026-11-12（北京时间）

**状态：** 已实现；完整检查与部署见[执行计划](../plans/2026-11-11-core-cache-asof-boundary.md)。

## 问题

Paper核心缓存按股票池与完整日线边界共享，原实现只判断TTL。同一天内时钟后退或并发请求逆序时，较早asOf会复用较晚请求已完成或仍在计算的上下文，返回的generatedAt也可晚于请求时点。服务回归已复现该问题；没有证据说明11月11日生产发生过这个时序，不能据此解释无买入。

## 决策

ResearchResultCache增加可选asOfMs，记录该次工厂所属请求的固定研究时点。受约束读取只复用asOf已知且不晚于请求上界的条目，包括在途任务；等时和前进时钟继续共享。同key较晚条目可在容量允许时替换为较早工作。

替换不能取消旧工作或提前释放活跃槽；旧完成/失败不能覆盖或删除替代条目。容量不足时拒绝新工作，并保留原条目供合法较晚请求共享。非有限上界在读取或修改缓存前拒绝，未知来源上下文不能绕过显式上界。无上界调用保持原合同。

Paper核心入口传入已有本轮拥有的asOf。键不加入每个quote tick，正常/降级TTL仍30/5秒、最多8缓存和活跃任务上限保持，合成榜的完整快照键不变。不修改策略、资金、Bridge缓存或网络预算。

## 验证与限制

缓存上界和服务接线十一项新增旧版十失败、一项兼容；另补替换工作仍占容量的回归。目标最初96项通过，最终全套、构建和发布验收记于计划。原未来日线/跨收盘隔离、前进时钟共享、缓存失败重试和容量回归保持。

本修复只限制Node核心缓存的来源请求时点，不证明上游报价或行业快照观测时点完整可审计，也不提供历史盘中回放。不能把该正确性修复称为提速、覆盖扩大、成交增加或胜率提升。
