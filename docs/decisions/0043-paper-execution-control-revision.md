# 0043：异步Paper计划绑定账户控制修订

日期：2026-11-10（北京时间）。状态：已实现，发布状态见[模块23计划](../plans/2026-11-10-paper-execution-control-boundary.md)。

## 问题

研究和通知会等待网络。旧轮次只重查日历、行情、现金和硬风险，不重新确认用户的策略选择、档位及暂停意图。双Store业务回归证明：等待期间切换到资金防守、切换策略、暂停再恢复、策略切走再切回，都仍会提交旧计划。内部同额重置和执行器stop也有相同表现。现有HTTP账户重置已拒绝在执行器运行时重置，不应把内部路径测试描述为已证明该HTTP保护失效。

## 决定

- Store提供只读的进程内`getExecutionRevision()`。暂停状态、策略和档位的成功实际变化递增；每次成功账户重置即使金额和选项相同也递增；相同值重复设置不递增。
- JSON修订属于内存事务快照：写盘失败恢复原修订，不留下已失败控制的假变化。该字段不写JSON，不改变持久世代，也不向客户端公开。重启没有可继续执行的旧Promise，无需持久化此修订。
- 只读计划服务在开始时捕获修订，研究返回后、记录研究/生成计划前检查。变化返回固定中文409冲突，客户端可按现有刷新流程重读，不在一个请求内自动重复昂贵研究。
- 自动执行器独立捕获修订及自身stop生命周期，在研究完成、通知返回及每笔提交前重查。失效明确记录watch-only，保留已提交成交；恢复或重新开始不能让旧轮次重新有效。
- 正常成交、估值、审计和风险检查点不推进控制修订。Broker继续检查当时资金、挂单、风险、T+1、报价和费用，避免自身第一笔成交使合法第二笔误停。

## 边界

它不提供多实例锁、多市场账户隔离或任意状态快照一致性，也不是资金流水版本。已发送通知无法撤回，已成交订单不会因stop或变更设置自动回滚。当前账户重置HTTP保护保留，生产没有重置、策略变更或测试订单。

验证与发布证据统一保存在模块23计划，避免把隔离夹具当生产交易表现。
