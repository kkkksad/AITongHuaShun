# 0004：东方财富只读行情与统一纸面执行边界

**状态：** 接受  
**日期：** 2026-07-11

## 背景

仓库新增了东方财富公开行情客户端、行情提供者和券商适配器原型。公开行情可用于研究和模拟交易，但项目仍没有真实账户认证、密钥管理、人工审批、独立执行网关和生产级审计能力。若券商适配器自行维护现金、持仓、费用和订单逻辑，会形成第二套绕过 `RiskEngine` 的执行路径。

## 决策

- `EastMoneyMarketProvider` 只读取公开行情，并在构造阶段拒绝 `live` 模式。
- 东方财富行情原型当前不接入主服务的 `MARKET_DATA_PROVIDER` 选择器；正式装配前必须补齐来源、授权、时区、交易日历、停牌和复权治理。
- `EastMoneyBrokerAdapter` 只模拟连接生命周期，不发送任何外部订单请求。
- 东方财富纸面订单、费用、幂等、风控、持仓和账户状态全部委托 `PaperBroker + RiskEngine + TradingStore`。
- `tradingEnabled=true` 或 `environment=live` 必须在构造阶段失败。
- 当前东方财富纸面适配器不是未来真实执行网关的基础类；真实账户和订单能力必须在独立权限域重新设计、测试和审计。

## 结果

优点：

- 东方财富公开行情可以作为研究数据原型验证，不扩大订单权限。
- 所有纸面订单继续经过统一风控、整手、额度、资金和幂等检查。
- 避免出现与 `PaperBroker` 不一致的第二套手续费、持仓和成交语义。
- `live` 配置和已废弃的实盘开关均默认拒绝。

代价：

- 东方财富行情尚未接入主服务配置，也没有生产级缓存、限流、授权记录和数据版本。
- 当前纸面适配器仅适合契约验证，不代表官方券商沙箱能力。
- 未来真实执行仍需要独立认证、账户白名单、逐笔审批、额度控制、审计和紧急停止机制。

## 被取代关系

本决策补充 [0003：真实行情只读接入与纸面执行隔离](0003-read-only-market-provider-boundary.md)，不取代其“行情读取与订单执行分属不同权限域”的原则。
