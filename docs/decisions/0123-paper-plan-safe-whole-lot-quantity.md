# 0123：Paper计划整手数量必须处于安全整数范围

日期：2026-11-13。状态：源码ea30922已推送部署，本地及实际生产API镜像禁网195文件3217后端、TS/Vite与全部发布保护通过；发布验收见[子计划](../plans/2026-11-13-paper-quantity-safe-integer.md)。

## 问题与决定

candidateQuantity用有界二分寻找满足真实费用、单笔本金和费用后单股权重的最大整手。其上界来自资金除价格，原来没有确认数量为安全整数。即使资金/价格都是有限数值，初始数量仍可超过JavaScript安全整数范围；权重/费用让首次检查失败后，二分可能在浮点相邻可表示数处反复得到相同middle，阻塞同步调用线程。

固定正常10元报价、100股、25%单股、最低佣金5、佣金0.03%、零滑点/固定预留，单笔上限等于本金：原实现对2万元和100亿元均正常完成，但本金1e20/1e308在独立进程中超过1500ms后被父进程终止。实际回归测试旧版分别超时5000ms失败，两个安全数量控制通过。它是调用函数的数值边界，不是生产2万元账户发生过该故障或近期亏损的证据。

仅增加两处检查：初始roundLot数量非安全整数直接返回0；相邻整手数量也是安全整数时才调用原fitsBudget。不截断成任意巨大可下数量、不更改比例/费用/现金或Broker。0042原先明确保留的一元保守手数上限继续保持；原相邻整手、严格本金cap和二分逻辑保持。
