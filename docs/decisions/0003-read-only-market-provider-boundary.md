# 0003：真实行情只读接入与纸面执行隔离

**状态：** 接受  
**日期：** 2026-07-11

## 背景

项目需要从确定性模拟行情逐步接入真实或延迟行情，但当前尚未具备真实交易所需的认证、审批、密钥管理、账户白名单、事务存储和独立审计能力。如果把行情接入与券商执行放在同一个开关或适配器中，误配置可能让研究进程获得不应拥有的订单权限。

## 决策

- 使用 `MARKET_DATA_PROVIDER=mock|akshare` 独立选择行情来源。
- AkShare 通过独立 FastAPI 桥接提供只读行情，TypeScript 服务通过 `AkShareMarketProvider` 消费。
- 使用 AkShare 时必须设置 `MARKET_MODE=paper`。
- 无论行情来源如何，当前唯一订单执行实现都是本地 `PaperBroker`。
- `REAL_TRADING_ENABLED=true` 与 `MARKET_MODE=live` 在启动阶段直接失败。
- 行情桥接令牌只从服务端环境变量读取，不进入浏览器、源码或 `VITE_*` 配置。
- Fastify 通过 `/api/capabilities` 声明行情来源、只读属性和纸面执行边界。
- OpenAPI 文档只描述研究、行情和模拟交易接口，不创建真实执行端点。

## 结果

优点：

- 可以用真实或延迟行情驱动模拟账户，而不扩大订单权限。
- 前端能够明确展示行情来源，避免把模拟成交理解为真实成交。
- 行情服务和订单执行服务可以在未来分别部署、授权和审计。
- 启动时失败策略降低了环境变量误配置的风险。

代价：

- AkShare 数据质量、授权条款、停牌、复权和交易日历仍需单独治理。
- 当前 FastAPI 桥接只有内存缓存，不具备高可用或持久化能力。
- PostgreSQL、身份认证、人工审批和独立执行网关仍需后续决策。
