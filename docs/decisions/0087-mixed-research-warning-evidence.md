# 0087：混合研究警告不能被已有诊断遮蔽

**日期：** 2026-11-12（北京时间）

**状态：** 已实现；验证与部署见[执行计划](../plans/2026-11-11-mixed-research-warning-evidence.md)。

## 问题

旧聚合器只在issue列表完全为空时记录`provider-warning`。同轮已有超时、预热、队列或覆盖不足，就会静默丢失其他警告存在的证据。只检查前8条、每条2000字符时，超预算的部分也无提示；审计不足以说明是否仍有未展开问题。

## 决策

- 按单条警告识别既有合同错误、超时、预热和队列分类，继续不把`unexpected keyword argument 'timeout'`当网络超时。
- 发现未匹配警告，或条数/字符超检查预算，就保留既有`provider-warning`。固定文案说明“未分类或未展开”，不声称知道原始根因。
- 沿用最多8条×2000字符检查、最多4项issue和既有7个白名单码；有generic时保留原优先级前三项加generic。覆盖数量始终独立保留，裁剪issue不改变覆盖事实。
- 内部两种“没有61根日线”固定消息仅在对应计数确为零时由覆盖证据解释；计数健康而出现矛盾消息则generic保留。
- 不传播原始URL、令牌、错误正文，不改交易许可、研究路由或执行行为；不能重建11月11日未保存的原始警告，也不是已证明的当日无买入根因。

## 验证

13项新增旧版10失败/3兼容；目标93通过，覆盖混合错误、满载裁剪、预算外第九条不读取、字符截断、覆盖矛盾和源数组不可变。原13项分类/固定文案回归保持。完整检查与发布回执见执行计划。
