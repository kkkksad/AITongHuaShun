# 0041：按需采样API进程资源，区间与口径独立于主机容量

- 状态：接受。
- 日期：2026-11-10（北京时间）。

## 背景

已有路由P95和失败窗口能发现慢接口，却不能区分API进程本身的计算、内存和事件循环压力。服务器休市时低负载不代表盘中容量，也不足以支持扩大上游并发、安装Redis/PostgreSQL或追求CPU满载。

## 决策

沿用受认证与no-store保护的`/api/system/performance`，增加可选`runtime.processResources`，旧响应继续可展示。每个Fastify实例独立持有一个监视器；首次请求才建立基线并启用Node原生20ms延迟直方图，应用关闭时disable。只保留一个基线、一个完成区间和有界原生直方图，不增加进程、数据库、Shell、磁盘扫描或网络请求。

CPU使用`process.cpuUsage`用户/系统时间差除以单调墙时跨度，100%表示一个逻辑核，可超过100%。间隔至少一秒才切换基线和重置直方图，短间隔返回上一个已完成区间，保留其原始开始/结束时间，避免快速刷新制造零值。计算跨度来自performance.now，不受系统时钟回退影响。

事件循环忙碌率取累积active/idle差值，P95取原生直方图并从纳秒转毫秒；缺样本返回null。内存单独记录最新测量时刻，只输出RSS、已用/分配堆、external和arrayBuffers白名单数值。RSS与堆重叠，external包含arrayBuffers，不将这些数值求和或当容器内存配额。

页面明确这是API进程资源，不是整机或其他容器，不代表单条路由耗用；没有完成区间显示预热，旧响应显示未接入。资源观察不改变路由健康状态、行情、策略资格、风险、资金或订单，也不从单次观察确定不交易原因。

## 代价与限制

打开过诊断后，原生20ms采样保持到进程关闭；暂无独立全主机/cgroup容量测量和长期资源趋势。各实例统计窗口独立，但测量对象都是所在Node进程，不宣称应用级CPU归属。系统时钟校准可能令显示的墙时开始晚于结束，实际跨度仍由单调时钟给出。
