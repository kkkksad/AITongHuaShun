# 0052：新增标的机会与总策略命中分开诊断

日期：2026-11-11；状态：实现和验证完成，发布见[持续计划](../plans/2026-11-10-overnight-strategy-and-loading.md)。

## 原因

原策略命中包含已有持仓；affordableCandidateCount按初始完整预算逐只计算，也未要求策略资格。因此“命中/可买大于0但无买单”可能是正确结果，不能据此归因执行故障。

## 合同

strategyCoverage新增可选newPositionFunnel，保留原计数以兼容历史。scope固定ranked-top-12；scannerCandidateCount是双扫描watch/focus/paper-buy去重数，consideredCandidateCount是按原比较器排序后的前12数量。其余计数均限于这12只：已有持仓、新标的、策略资格通过的新标的，以及按原初始完整预算独立可形成整手的新标的。快照回退资格也纳入资格计数，但不称为真实历史策略匹配。

plannedBuyCount取最终operations的paper-buy-plan数；allowNewPositions取原档位与路由的全局新增许可，资格计数与该许可分开。独立金额通过不代表多单累计资金足够，不替代候选质量、每日额度、报价复核及Broker最终许可。漏斗各级差值也不能当作唯一、互斥的拒单原因。

实现保留排序、前12选择、信号、参数与经济操作；在现有初始金额计算上复用结果，不增加历史请求。诊断跟随现有strategyCoverage进入运行审计，本模块没有新增SQLite漏斗白名单，不宣称已长期归档该字段。

页面把“可买”改为“金额可覆盖”，显示扫描范围、漏斗和全局许可；旧报告缺字段时不补造零。真实历史计划说明同步修正，形态路由仍不等同独立样本外收益证据，合成演示继续明确标记。

## 验证

旧版后端7项和页面1项新增能力失败复现；修复后覆盖只匹配已有持仓、新股可成整手/受费用整手限制、全局禁买、扫描去重与12只边界、快照回退和新旧页面兼容。完整测试、隔离浏览器与发布核验结果记录在执行计划。
