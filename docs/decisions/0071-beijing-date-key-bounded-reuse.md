# 0071：北京时间日期字符串的单槽复用

状态：接受。日期：2026-11-11（北京时间）。替代关系：无。

N模块已把每日基线的逐成交日期格式化改为数值日界，但每次账户/日历读取仍重复生成同一个北京日期。最新本机12股/120根合成榜CPU采样墙钟7.923秒，getChinaDateKey独占约1.268秒；采样有额外开销，不是线上端点P95。

getChinaDateKey仅保存最近一次成功格式化的UTC+8日编号与不可变日期字符串，常量空间。相同日编号且偏移后时间在Date范围内时返回旧字符串；其余沿用原Date/ISO生成，成功后才覆盖单槽。保留主Date非法检查和偏移溢出RangeError，特别防止极限日期在同一缓存日命中掩盖错误。负纪元用floor，时间回拨和Date对象修改按当前数值处理。

不缓存账户、风控基线、订单、报价或交易许可；每次原有账务重建照常进行。节假日/交易时段/日历覆盖规则未改变，没有新增日期来源或持久文件。

12项新回归中旧版三个成本合同失败，其余九项语义通过；修后目标五文件83项通过。覆盖午夜±1ms、回拨、同刻不同时区、闰日/年界/负纪元、修改Date、非法主时间和偏移溢出，以及5007个分散/极限时间的原函数对照。2000组账本与1224次固定真实回测完整结果相同；完整测试/构建与发布见[流水](../plans/2026-11-10-overnight-strategy-and-loading.md)。
