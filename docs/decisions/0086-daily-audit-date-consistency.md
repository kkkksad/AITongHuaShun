# 0086：每日复盘审计日期一致性和实际时间排序

**日期：** 2026-11-12（北京时间）

**状态：** 已实现；验证与发布见[计划](../plans/2026-11-11-daily-audit-time-selection.md)。

## 问题

每日入场说明原先直接信任审计内的显式交易日，日期字段为null/数字时又按缺省兼容；因此实际属于昨天的open风险路由可能被当作今日证据。最新运行与旧通知路由回退按ISO字符串排序，不同偏移或等价时间表示会误选。这些是受控反例证明的潜在缺陷，尚未证明发生在11月11日生产记录。

## 决策

- 审计实际时间必须有效并已在报告截止内。北京实际日期与显式交易日必须一致；仅字段缺省时按实际日期兼容，冲突/null/非字符串不参与当日说明。
- 最新选择使用数值时间降序；同一时刻保留输入稳定顺序，不根据时区字符串猜测新旧。此规则同时用于有效盘中run和旧通知路由回退。
- 继续优先当日有效盘中运行，保留实际买入、资金拒单、数据降级和风险路由的原诊断优先级；缺证据回到未知/覆盖缺口，不构造不存在的依据。
- 不改历史审计、账户、订单、策略或执行。0085日内汇总已使用相同日期一致性，此次使单轮说明与汇总保持一致。

## 验证与边界

八项新增回归旧版六失败、两兼容，修复后目标76项通过，包含实际旧日/显式错日/null/数字、UTC偏移、等价时刻稳定性、通知路由回退、未来/坏时间和不可变输入。

生产当日254条run的白名单投影（时间、session、交易日、regime、quality、source、漏斗）在新旧纯builder中得到完全相同的`entryReview`；盘中225条。输入没有完整skip原文或账户对象，因此只证明该固定投影兼容，不声称完整生产日复盘相同。完整检查与发布回执见执行计划；前端、共享合同与Python未改。
