# 0028：Paper 完整持仓周期保存净成交结果

- 状态：接受，净结果证据已发布；后续[决策0030](0030-paper-risk-consumption-and-recovery.md)已实现主风险消费和检查点。
- 日期：2026-11-10（北京时间）。
- 被取代关系：不取代账户累计净盈亏、日权益基线或研究 FIFO 样本定义。

## 背景

RiskEngine 有连续亏损接口，但主 Broker 尚未接线。账户累计已实现净额包含买费，却不能把每次买入的费用当作一笔亏损交易；当前持仓均价不含买佣金，部分卖出与加仓也不能被重复算作完整交易。已完成订单在七天后清理，不能依赖无限订单历史重建风险样本。

## 决策

仅在当前 A 股 Paper 内部账本增加 `paperCycle` 和 `paperFillLedger`。单股从空仓买入到再次全部卖空为一个周期；累计真实买入本金/费用、卖出本金/费用和股数，只有最后一笔平仓才写入一次闭合结果。完整周期净额为卖出本金减卖费、全部买入本金及买费；在全部退出时所有成本已经实现，无须在每次部分卖出时分摊并舍入买费。中间加仓与退出不会重置周期；该字段不改变现有现金、均价、持仓级盈亏或账户级盈亏算法。

旧持仓或种子持仓没有入场证据时，不回填零费用；即使后来加仓，最终闭合仍写 `missing-entry / netPnl=null`。新空仓开启的周期可建立完整证据。不能把未知周期算成盈利、亏损或已验证策略样本。

闭合序列递增，保存最近512项，按成交记账顺序排列，与订单的保留天数无关。读取返回副本；终态成交重放和重复客户端订单不会再次追加。显式账户重置清除未闭合和已闭合证据。后续风险检查点必须记录消费序列，并对超出512项的消费缺口明确处理，不能静默遗漏。

JSON 在同一原子文件替换中保存成交、现金、仓位、周期结果和审计。所有新增的显式持久字段在载入任何剪裁写盘前验证；缺字段兼容旧文件，非法净额、股数、序列、日期或证据类型拒绝载入且保留原文件。该设计沿用单进程 JSON 的限制，不提供多进程事务；本模块尚无写盘失败内存回滚，后续[决策0031](0031-json-ledger-atomic-mutations.md)已统一补齐。

JSON 的 T+1 锁定与快照统一使用注入时钟的北京时间日期，便于跨日故障回放；没有改变真实 A 股 T+1 规则。

## 结果与代价

提供可复现的含费用完整交易结果，并为幂等风控消费准备证据；本模块单独发布时尚不触发主系统连续亏损熔断，随后由0030接通。每个在持仓中的股票增加固定大小的累计证据，闭合列表固定上限；没有保存 tick、完整回放日志或新增真实执行能力。旧入场资料、已裁剪旧交易和历史权益峰值仍不能补造。

验证与独立发布记录见[执行子计划](../plans/2026-11-10-paper-fill-risk-integration.md)。
