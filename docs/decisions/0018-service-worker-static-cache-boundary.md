# 0018：Service Worker只缓存公开静态资源

- 状态：接受
- 日期：2026-11-05
- 被取代关系：收窄原kairos-v2默认GET缓存行为，不取代服务端认证决策0006。

## 背景

原Worker把未命中导航或/assets的GET当作静态资源，以Cache API显式保存。Cache API不会自动执行HTTP no-store语义，账户/订单/认证会话因此可能长期显示旧200，即便网络状态已改变或应返回401。服务端认证仍检查网络请求，此缺陷不会授予真实下单权限，但缓存不得冒充当前业务或身份状态。

## 决策

- 仅处理同源GET：已知SPA页面导航、公开HTML壳、manifest/两尺寸图标白名单及/assets。其他请求不respondWith、不查缓存，由浏览器网络处理；包括所有API、查询、非GET、未知路径和跨源读取。
- 已知页面和打包资源network-first，断网仅回退当前版本静态缓存；图标/manifest可cache-first。仅成功basic响应可写，导航/HTML壳还须text/html。错误响应不覆盖已存资源。
- 使用kairos-v3专属读取，不能从其他CacheStorage名称搜索旧业务响应。安装保留可成功读取的公开资源；激活先删除旧kairos-*缓存再claim，waitUntil覆盖这些工作；无关命名缓存保留。
- 业务与认证状态的前端同步继续由REST、受保护会话及进程内Query缓存承担，不新增业务离线模式。

## 结果与代价

旧v2中的账户/认证/订单响应在新Worker激活时清除，离线API会按网络失败处理，不显示旧数据代替当前事实。更新需要客户端安装/激活新Worker；服务器部署不能证明所有已打开浏览器已更新。升级后静态缓存需要重新预热，旧版本不再作为回退来源。公开HTML壳只包含前端入口，不包含账户数据；未来若引入服务端个性化HTML，必须重新审查此白名单。

## 验证

37项执行原SW脚本的回归覆盖fresh账户、会话401、POST后GET、legacy cache、离线、同源/跨源/未知路径、静态及导航、响应过滤与安装/激活次序。独立浏览器生命周期与完整发布结果见[夜间计划](../plans/2026-11-05-overnight-module-upgrades.md)。
