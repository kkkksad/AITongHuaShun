# 0014：Paper 可用现金包含订单必要成本

- 状态：接受
- 日期：2026-11-05

## 背景

[决策0010](0010-no-fixed-paper-cash-reserve.md)取消固定比例预留，但并不允许费用透支。原Broker和Store只检查或冻结限价本金，市价滑点和成交佣金可能令总现金变负；旧JSON挂单在重载后也会遇到该边界。

## 决策

1. Store保留限价买单本金冻结；Broker使用一个纯成本工具，按现有滑点、限价钳制、两位成交价和两位佣金顺序估算执行成本。挂单完整预算为原限价本金与舍入后限价成交成本的较大值，差额仅用于必要成本。
2. Broker对外账户的可用现金再扣除待买单的成本补差。费用由当前Broker配置派生，不增加OrderRecord字段，不迁移JSON版本；旧挂单同样受当前成本约束。总现金、权益、未实现收益和持仓估值不因预占预算改变。
3. 提交时在原风控优先级内检查完整资金需求；实际撮合前再次扣除其他待买单的完整预算，核对本单真实现金流。可用资金不足即审计拒绝，不成交、不挪用其他挂单预算。卖出所得不足以覆盖佣金时，也必须有足够未承诺现金支付差额。
4. 两种Store在修改持仓或现金前保留独立余额兜底；回测账户上下文和曲线通过Broker读取，与线上模拟盘使用同一资金口径。原始Store现金接口只掌握本金冻结，不能当成含执行费率的对外余额。
5. 保留成交价格、佣金、滑点、单笔和单股硬限额、T+1、幂等及其他风控。浮点比较只容忍机器计算误差，不能放宽为一分钱额度，也不重写历史成交或现金。

## 结果与代价

现金恰好够本金、但不足费用的订单会更早被拒；其他挂单占用的必要费用不会被新单重复使用。费率变更或旧挂单预算不足时，显示的可用现金可能低于旧版本，表示实际成本约束而非固定比例预留。实时账户派生需检查当前待买单，性能验证与经济结果控制记录在夜间计划。

## 被取代关系

补充决策0010的必要费用含义，取代仅凭本金判断可用资金足够的实现；不恢复任何固定比例或分时总仓位预留政策。
