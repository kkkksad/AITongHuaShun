# 0090：初始化状态与业务快照并行读取

**日期：** 2026-11-12（北京时间）

**状态：** 已实现；完整验证与部署见[执行计划](../plans/2026-11-11-bootstrap-independent-reads.md)。

## 问题与决策

fetchTradingBootstrap旧版先等health/capabilities，再发起市场、账户、持仓、最近50订单和风险限额读取。五类GET不依赖前两个响应的内容，因此多等一个网络波次。

把fetchSystemStatus与五类原GET放入同一个Promise.all。总数仍为七个GET，共用原AbortSignal、Cookie和认证generation机制；调用位置仍由现有认证生命周期启用。任何必需请求失败仍拒绝整个初始化，不返回部分账户，也不改变查询缓存或WebSocket覆盖层。并行读取不提供服务端原子快照，已有实时事件覆盖层和生命周期门继续负责迟到保护。

## 验证与限制

四项新增回归旧版三失败、一项错误兼容通过。状态100ms/业务50ms时150→100ms；业务200ms时仍等完整200ms，原七请求、只读方法、会话Cookie、同信号取消和错误整体拒绝均保持。认证generation、重连与实时合并等目标108项通过。

同一本机HTTP、每响应固定80ms、两轮ABBA八次完整读取，七请求和返回报告均一致：旧版203.903/187.930/190.447/189.513ms，新版94.469/93.052/95.908/95.470ms。该测量包含本机受控延迟与调度，仅验证省去一波等待，不能当作生产页面P95、真实网络或服务器容量结论。没有增加轮询、来源请求、重试、下单或账户修改；完整前端/构建和发布验收另记于计划。
