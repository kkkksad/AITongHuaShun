# 0024：Paper计划显式标记候选分区

- 状态：接受
- 日期：2026-11-09

## 背景

Paper计划已经记录操作动作和阻塞原因，但页面需要把“没有交易”与“等待确认、持仓管理、可执行机会”分开，否则用户只能看到一串混合记录。

## 决策

每个`PaperTradingOperation`附带可解释的`tier`：`observation`观察区、`pending-confirmation`待确认区、`executable`可执行区、`holding`持仓区、`holding-exit`待退出区。旧客户端缺少字段时按动作兼容；新计划在返回前为每条操作补齐分区，不改变数量、金额、策略资格、费用或风控。

映射只使用计划动作：paper-buy-plan进入可执行区，paper-sell-plan进入待退出区，hold进入持仓区，blocked进入待确认区，observe进入观察区。进入可执行区仍只是Paper计划，不等于订单已提交或成交；真正提交前继续由执行器和Broker重新检查行情、资金和风险。

## 结果与代价

前端研究管线直接显示分区和原始原因，用户可以看到是正常观察、待数据/确认、已有仓位还是可执行计划。没有增加强制成交策略，也不为达到目标而放宽策略和资金约束。

服务端覆盖测试验证每条操作均有分区，既有策略、整手、费用、T+1和适应性测试保持通过。

## 完整候选展示补充（2026-11-10）

新增可选`candidatePool`，合并本次两扫描器返回的股票、持仓与计划中的逐股记录，以证券代码去重。此池覆盖本次扫描范围，不代表全部市场；原`qualitySummary.candidatePoolSize`仍是最多12只计划排序候选。两者不混用。

展示优先级为待退出、持仓、买入计划就绪、待确认、观察。逐股实际计划原因优先；全局CASH观察限制只附给确实进入本次计划排序池而未形成逐股记录的股票，明确标为全局证据。扫描器关注但无逐股计划的记录保持观察并标为未评估，不臆造历史通过、策略命中或具体门槛；回避项保留扫描风险理由。持仓不因扫描评分或买入拦截变成新买入候选。

全部去重股票参与分区计数，最多返回120条优先明细，并明确省略数；不是隐藏剩余数量。前端提供各区筛选、原因来源与后续复核说明，旧报告无该字段时明确缺少完整分区，保留原计划记录。`executable`在此面板显示“买入计划就绪”，仍须执行器与Broker最终复核。

该模块只派生解释视图，不参与信号、预算、排队或提交，不新增行情请求。下一核对内容是通用说明，尚未计算逐股门槛差值或下一触发时间，也没有增加候选池持久调度。
