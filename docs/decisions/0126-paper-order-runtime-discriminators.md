# 0126：Paper内部订单方向与类型须经运行时校验

- 状态：接受；发布状态见[执行计划](../plans/2026-11-13-paper-order-discriminator-validation.md)。
- 日期：2026-11-14（北京时间）。

## 已复现

TypeScript类型不能校验运行时传入值。HTTP下单入口已有Zod枚举，但原PaperBroker和RiskEngine没有方向/类型枚举校验。`side="wrong"`会跳过买入资金/权重和卖出持仓/T+1分支；Store遇到未知方向时并非可靠拒绝，导致空账户记录没有实际资金/库存变化的filled，已有当日锁仓时还可被当卖出消耗。未知type沿市场路径处理。

实际89cc7fc版Broker/RiskEngine、两Store本地隔离复现：纯现金未知方向记filled100股、佣金5却现金库存不变；当日锁定300股/可卖0时未知方向仍filled300、库存归零。38新增业务反例旧版32失败/6控制；当前真实账户没有此类订单证据，不把合成反例归因为历史亏损。

## 决策

共享纯函数仅校验side为buy/sell、type为market/limit，依次返回固定错误码INVALID_ORDER_SIDE/INVALID_ORDER_TYPE。PaperBroker保留原重复clientOrderId返回优先，再在任何行情/成本/风险/创建订单前执行校验。坏枚举只追加固定拒绝审计并抛错，不将非法枚举包装成订单写入主账本；审计不记录原始任意payload。写入审计失败沿既有存储错误传播，不继续创建订单。

RiskEngine独立输入也校验，放在原暂停检查后、行情检查前；此前的账本缺口/熔断/实盘开关/暂停优先级不变。合法请求继续沿原费用、现金、单股、限额、T+1和幂等模型。

三个具有源码指纹的资金/退出/完成入场离线研究脚本显式纳入新共享校验源，只有来源元数据新增，不改研究参数。离线native适配器完整意图检查仍需单独修复；本模块不将Broker拒绝等同于研究整体已经失败。
