# 0051：Paper运行阶段耗时使用单调时钟

日期：2026-11-11；状态：B1已部署，B2归档/页面已实现，实际发布结果见[夜间计划](../plans/2026-11-10-overnight-strategy-and-loading.md)。

## 原因

自动执行器内存已有startedAt/finishedAt，但持久审计不保存，且两条持久运行的间隔包含60秒完成后调度、记录合并和运行耗时，不能解释成计算耗时。墙钟也可能校时回拨。

## 合同

每轮独立PaperExecutionTimer，使用performance.now；可注入时钟仅用于离线测试。timing包含固定clock=monotonic、scope=run-before-audit、unit=ms，以及totalMs/researchMs/notificationMs/executionMs，至多三个阶段标量，不保存请求内容。

- totalMs：进入runOnce至生成最终运行对象，排除最后一条运行审计写盘；不是CPU时间，也不是请求P95。
- researchMs：buildCurrentPaperTradingPlan整个调用，含缓存等待、命中或实际研究；不能将该值全部解释成上游网络。
- notificationMs：实际调用计划通知和成交事件通知的时间之和；通知内部可能决定不发送，不能据此判断发送成功。
- executionMs：本地订单预检及逐笔报价/控制复核、Broker提交、回调和逐笔决策审计时间之和；不含通知。没有实际提交也可能有预检耗时。
- 阶段没有运行为null；合法已测0保留0。失败任务在finally保留耗时，原失败继续传播。非有限、回拨或超过24小时的诊断样本为null，不补0或截断伪值。
- startedAt/finishedAt墙钟原样进入审计；可能回拨，不能反算timing。合并签名不包含耗时，保留既有心跳合并和内存历史上限，持久样本不能当作所有运行的无偏分布。

研究、通知和提交阶段不重叠；total还包括各阶段间账户/策略上下文准备。并发调用各自建计时器，正在运行时的跳过不继承原轮耗时。诊断时钟异常不影响交易任务，未增加调度、网络、交易许可或任何测试生产订单。
