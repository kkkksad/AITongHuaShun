# KAIROS Quant 未来优化蓝图

**文档状态：** 目标设计，不代表当前已经实现
**更新日期：** 2026-07-17
**当前事实：** 以 [当前状态](../status/current-state.md) 为准
**交易边界：** 以 [交易与数据安全边界](../safety/trading-boundaries.md) 为准
**系统优化执行：** 以 [2026-07-16 系统优化实施计划](../plans/2026-07-16-system-optimization-roadmap.md) 为当前性能、代码边界和策略验证主计划

## 目标

KAIROS Quant 的目标不是寻找一套永远有效的战法，而是建设一个能够识别市场环境、选择适配策略、控制组合风险、持续做样本外验证并保留完整证据的研究和模拟交易系统。

系统优先追求以下结果：

1. 少犯大错，先控制回撤和错误暴露，再追求收益。
2. 不依赖单一策略，根据市场状态切换、组合或停用策略。
3. 只使用决策时点已经可获得的真实数据，结果可复现、可追溯。
4. 先通过历史样本外验证和本地 paper，再评估外部模拟盘。
5. 不把单日盈利、回测高收益或启发式评分描述为稳定盈利能力。

## 核心原则

- **市场状态先于策略：** 先判断趋势、波动、宽度、流动性和风险，再决定哪些策略有资格运行。
- **现金也是策略：** 状态不明确、数据降级或策略退化时，允许不交易。
- **多策略不是多下单：** 策略数量增加必须配合去相关、风险预算和冲突消解，不能把同一方向信号重复叠加。
- **样本外优先：** 参数选择、状态识别和策略比较必须使用滚动训练/验证/测试边界。
- **真实数据有来源：** 行情、新闻、财务、全球市场和账户数据必须保留供应商、时间戳、时区、授权和降级状态。
- **研究与执行隔离：** 研究系统只能生成信号和订单意图；外部订单必须经过独立网关、风控、审批和回报核对。
- **自动优化不自动放权：** 系统可以自动提出参数和权重，但不能自行扩大额度、账户权限或真实执行范围。

## 方向一：市场状态驱动的策略选择

### 1.1 市场状态模型

第一优先级是新增 `MarketRegimeEngine`，按日内和日线两个层级输出市场状态、置信度、证据和失效条件。

建议先采用透明、确定性的六类状态，不直接上黑盒分类器：

| 市场状态 | 主要证据 | 优先策略 | 应停用或降权 |
| --- | --- | --- | --- |
| 上升趋势、低波动 | 指数和多数行业站上 MA20/MA60，宽度改善，波动受控 | 趋势健康、均线、海龟、低波趋势 | 高频反转、过早止盈 |
| 上升趋势、高波动 | 中期趋势向上，但振幅、分化和追高风险高 | 强势回踩、洗盘恢复、小仓位动量 | 满仓追涨、密集网格 |
| 区间震荡、低波动 | 均线走平，突破失败率高，成交稳定 | 均值回归、受控网格、分批交易 | 长周期突破追随 |
| 区间震荡、高波动 | 宽幅来回、板块快速轮动、假突破多 | 小仓位反转、事件观察、快速降风险 | 加仓摊平、宽松止损 |
| 下行或 risk-off | MA20/MA60 下行，跌停扩散，宽度恶化，全球风险偏弱 | 资金盾牌、减仓、持有现金 | 新开趋势多头、抄底型网格 |
| 不明确或数据降级 | 状态置信度不足、数据过期、来源冲突 | 观察、现金、只生成研究报告 | 自动新增仓位 |

状态特征至少包括：

- 上证、深证、创业板、沪深 300 的 5/20/60 日趋势与波动率。
- 全市场上涨/下跌家数、涨停/跌停家数、成交额和流动性变化。
- 行业收益离散度、领涨持续性、行业轮动速度和主力净流入可用性。
- 个股横截面动量、回撤、量价结构、停牌、ST、涨跌停和一字板状态。
- 全球主要指数、人民币、商品等滞后影响特征，但不得使用未来时区数据。
- 新闻和公告发布时间，只允许使用决策时点之前已经发布的内容。

### 1.2 策略资格矩阵

每种策略必须声明：

- 适用市场状态和禁用状态。
- 最低状态置信度、最低数据质量和最少历史样本。
- 最大仓位、最大行业暴露、止损/退出规则和冷却期。
- 最近 20/60/120 个交易日的样本外指标和退化阈值。
- 与其他策略的信号相关度和冲突处理优先级。

策略路由器不直接选“历史收益最高”的策略，而是按以下顺序决策：

1. 数据质量和市场状态是否可用。
2. 哪些策略在当前状态下有资格运行。
3. 合格策略最近的样本外表现是否高于各自基线。
4. 多个信号是否指向同一标的、同一行业或同一风险因子。
5. 组合风险预算允许多少新增暴露。
6. 置信度不足时返回 `hold-cash`，不强制产生订单。

为避免状态在边界附近反复切换，应增加滞回规则：状态连续确认 2 至 3 个观察窗口后再切换，切换后设置冷却期，极端风险状态可以立即生效。

### 1.3 策略组合而不是单策略死磕

建议把现有策略归入以下策略族：

- 趋势族：均线、海龟、动量、趋势健康、低波趋势。
- 回踩族：强势回踩、安静回踩、洗盘恢复。
- 震荡族：均值回归、受控网格、RSI 反转。
- 防守族：资金盾牌、减仓、现金等待和熔断恢复。
- 事件族：新闻、公告和全球市场影响，完成历史时间对齐前只做观察信号。

同一策略族只保留少量低相关代表，避免参数稍有不同却实质相同的策略重复占用资金。路由结果必须解释“为什么启用、为什么停用、为什么保持现金”。

### 1.4 当前已落地的确定性路由 1.1

当前本地 paper 原型已经实现第一版六状态资格矩阵，但它仍是确定性研究规则，不是经过长期样本外校准的盈利概率模型：

| 市场状态 | 当前优先策略 | 当前使用与回避原则 | 开盘 / 上午 / 下午 / 尾盘最大仓位 |
| --- | --- | --- | --- |
| 上升趋势、低波动 | 低波趋势、趋势健康 | 趋势、斜率和上涨宽度同步时使用；宽度转弱或波动抬升时回避 | 55% / 70% / 82% / 90% |
| 上升趋势、高波动 | 安静回踩、洗盘恢复、强势回踩 | 中期趋势仍在且回踩确认时使用；追涨和宽松止损回避 | 40% / 50% / 65% / 75% |
| 区间震荡、低波动 | RSI、布林带均值回归 | 均线走平且边界稳定时使用；趋势突破后回避 | 35% / 45% / 55% / 65% |
| 区间震荡、高波动 | 资金盾牌、安静回踩 | 仅小仓位等待高质量回踩确认；摊平和反弹追入回避 | 30% / 38% / 48% / 58% |
| 风险收缩 | 资金盾牌、减仓、现金 | 优先降低已有风险；禁止新增多头仓位 | 35% / 35% / 35% / 35% |
| 状态不清或数据降级 | 资金盾牌、现金观察 | 等待来源和状态恢复；禁止自动新增仓位 | 30% / 30% / 30% / 30% |

自动 paper 执行会在 09:30、10:15、13:00 和 14:15 进入四个复核阶段，买入必须同时通过当期总仓位上限、现金储备、每日/单轮笔数、整手、T+1、幂等和熔断检查。卖出降风险不受买入仓位节奏限制。状态边界的连续确认和跨窗口滞回仍是下一阶段工作，因此当前规则不能被描述为“自动找到最赚钱策略”。

当前还增加了独立的跨市场只读上下文：全球指数与国内期货股指、工业品和贵金属的快照及 5/20/60 日结构被归纳为 `risk-on / neutral / risk-off / mixed`，再映射为优先和降权策略族。来源不足或方向冲突时返回现金观望；该结果尚未完成时区对齐和历史增量价值验证，因此不会自动覆盖上表的 A 股 paper 路由或放大仓位。

## 方向二：真实历史数据与可信实验平台

当前策略排行榜仍有合成历史成分，下一阶段应优先替换，而不是继续在合成数据上堆策略。

### 2.1 数据层

- 建立带版本的数据目录，记录供应商、授权、抓取时间、交易日历、复权方式和字段字典。
- 长期保存紧凑日线、复权因子、指数、行业、财务快照和特征，不默认保存无限 tick 或新闻全文。
- 显式处理新股、退市股、停牌、ST、涨跌停、一字板、分红送转和指数成分变化。
- 使用当时可见的股票池，避免只用今天仍上市的股票造成生存者偏差。
- 每次实验绑定数据版本、代码提交、参数、随机种子和成本模型。

### 2.2 回测与验证

- 把浏览器合成回测和服务端排行榜迁移到同一套真实历史回测内核。
- 使用滚动训练、验证和完全隔离测试集；参数选择不得查看测试期结果。
- 对标签重叠的样本使用时间隔离或 embargo，避免相邻窗口泄漏。
- 建模佣金、最低佣金、印花税、过户费、滑点、整手、T+1、涨跌停和无法成交。
- 同时报告收益、最大回撤、Sortino、盈利因子、换手、持仓集中度和最差月份。
- 对策略状态分别统计表现，例如趋势策略只在趋势期是否有效，而不是只看全样本平均值。
- 建立基线：沪深 300、等权股票池、现金和简单均线策略，复杂模型必须稳定超过基线才有保留价值。

### 2.3 防止过拟合

- 限制参数自由度和搜索空间，记录每次试验数量。
- 优先选择参数平台区，而不是单个尖峰最优值。
- 对策略做扰动测试：成本增加、成交延迟、价格滑点和起始日期变化。
- 连续多个样本外窗口退化后自动降权或停用，不允许自动放宽风险阈值挽救策略。
- 机器学习只在透明基线完成后引入，先用于状态分类和排序，不直接绕过风控生成订单。

## 方向三：接入真实同花顺 App / 模拟环境

这里的“真实同花顺”指真实的同花顺模拟账户或官方策略环境，不等于真实资金自动交易。

### 3.1 接入顺序

1. **能力调查：** 确认同花顺官方提供的模拟盘、SuperMind、开放接口、授权方式、限频和服务条款。
2. **只读对账：** 优先读取模拟账户、持仓、订单和成交回报，不允许提交订单。
3. **信号导出：** 继续使用当前 SuperMind 信号包，由用户在官方环境人工复核。
4. **模拟订单网关：** 仅在存在官方、稳定、可测试的模拟接口时，建立服务端 `TongHuaShunSimulationGateway`。
5. **人工批准：** 每笔外部模拟订单必须先进入批准队列，显示标的、方向、数量、理由、风险和幂等键。
6. **回报核对：** 以同花顺返回的订单/成交为准，对本地意图、外部订单和成交做三方对账。

### 3.2 明确禁止

- 不使用桌面点击脚本、图片识别或浏览器自动化代替稳定交易 API。
- 不读取或保存同花顺网页登录 Cookie、浏览器 Token、短信验证码和明文密码。
- 不把凭据放进 React、`VITE_*`、源码、Git、日志或智能体上下文。
- 不通过当前 `TongHuaShunPaperAdapter` 改一个开关就启用外部订单。
- 不在没有官方接口、授权和回报核对的情况下声称“已经接入同花顺”。

### 3.3 目标架构

```text
Research / Regime Router
          │ 只生成信号
          ▼
Order Intent + Risk Check
          │
          ▼
Human Approval Queue
          │ 独立身份和额度
          ▼
TongHuaShun Simulation Gateway
          │ 官方模拟接口 / SuperMind
          ▼
Order / Fill Reconciliation + Audit
```

模拟网关必须具备账户白名单、标的白名单、单笔/单日额度、100 股整手、T+1、价格偏离、幂等、撤单、熔断、超时状态查询和紧急停机。任何真实资金能力继续作为独立项目推迟。

## 方向四：组合级风险和资金管理

单票策略胜率不能代表组合安全。需要新增 `PortfolioAllocator`：

- 按策略、行业、风格和相关性分配风险预算。
- 限制单票、单行业、同一风险因子和总权益暴露。
- 根据市场状态动态调整现金储备，而不是始终保持固定仓位。
- 低置信度信号只允许观察或极小 paper 仓位。
- 组合达到日内/周度/滚动最大回撤后自动减仓或暂停新增仓位。
- T+1 锁定仓位必须计入隔夜风险，不能把不可卖数量当作可用风险额度。
- 资金不足时在生成计划阶段消除不可执行订单，不创建注定拒绝的订单。

评估目标从“胜率最高”改为多目标约束：控制最大回撤、提高风险调整收益、减少无效换手、保证足够样本，并限制最差情形损失。

## 方向五：新闻、财务和全球市场因子

- 新闻建立去重、实体识别、发布时间和影响窗口，不只做标题情绪。
- 公告、业绩、估值和财务数据必须使用 point-in-time 快照，禁止用后来修订数据回填过去。
- 全球市场影响按中国开盘前可见信息对齐时区，分别验证隔夜和盘中影响。
- 板块资金流只在来源和口径稳定时使用；公开主力净流入不等同于授权 Level-2。
- 每个新增因子必须先做增量价值检验，不能因为数据多就默认有预测力。

## 方向六：受控的自动优化

自动优化应形成“提出候选、离线验证、paper 影子运行、人工晋级”的闭环：

1. 每日收盘后更新数据质量报告和特征。
2. 对当前状态下的策略做有界参数搜索。
3. 与固定基线和当前生产 paper 参数比较。
4. 新参数先进入 shadow 模式，只记录本来会做什么，不实际提交模拟订单。
5. 满足最少样本、最大回撤和稳定性门槛后，由人工批准晋级。
6. 保存晋级、拒绝和回滚原因；表现退化时自动退回上一稳定版本。

系统不得根据一天收益自动改策略，也不得用当天收盘后的信息修改当天已经发生的决策记录。

## 方向七：存储、部署和可观测性

### 7.1 存储控制

- 本地研究：紧凑 Parquet 日线/特征文件加 SQLite 或元数据索引。
- 服务器：PostgreSQL 保存账户、订单、审批、实验和审计；对象存储保存版本化研究数据。
- 原始 tick 默认不落盘；新闻默认保存元数据、摘要、哈希和链接，不保存无上限正文。
- 交易明细和审批审计长期保留；高频运行日志按天轮转和压缩。
- 设置磁盘配额、缓存淘汰、备份恢复演练和数据版本清理规则。

### 7.2 运行保障

- 服务健康检查拆分为前端、API、行情、研究数据、数据库和外部模拟网关。
- 增加策略计算耗时、数据延迟、拒单原因、状态切换、仓位风险和回撤指标。
- 研究接口采用后台任务和结果缓存，避免策略排行榜计算阻塞页面并被误报为“后端未启动”。
- 云端部署使用 HTTPS、进程守护、自动重启、共享会话、备份和告警。
- 外部模拟网关与研究服务独立部署，默认关闭并最小权限运行。

## 方向八：每日工作流和可检查结果

### 盘前

- 检查三项服务、数据新鲜度、市场日历和账户基线。
- 生成市场状态、允许策略、观察池、持仓风险和现金计划。
- 数据降级时直接标记 `hold-cash`。

### 盘中

- 每次运行记录市场状态、策略、候选、拒绝原因和最终本地 paper 订单。
- 状态显著改变时重新评估策略资格，但使用滞回规则避免频繁切换。
- 任何资金、T+1、熔断或数据质量拦截都必须留下审计记录。

### 盘后

- 对比盘前计划、实际信号、模拟订单、成交、未成交和跳过原因。
- 分解收益来源：市场、行业、选股、仓位、成本和偶然暴露。
- 按市场状态统计策略效果，不因单日盈亏立即改参数。
- 生成下一交易日的研究问题和 shadow 实验，不自动扩大权限。

## 方向九：研究界面、变盘雷达与跨市场观察

详细实施和验证记录见 [2026-07-16 市场智能升级计划](../plans/2026-07-16-market-intelligence-upgrade.md) 和 [2026-07-16 真实策略样本与跨市场研究计划](../plans/2026-07-16-cross-market-strategy-upgrade.md)。本方向的目标是让研究页面更容易使用，同时把“看起来像预测”的分数升级为有定义、有样本边界、可回测的统计结论。

### 9.1 UI 模块化

- 市场页按 `A 股概览`、`变盘雷达`、`个股研判`、`板块形态`、`港股观察`、`期货观察` 和 `事件资讯` 七个任务页签拆分，避免所有模块同时堆叠。
- 指数保留为市场入口信号，昂贵历史研究只在对应页签激活时加载。
- 概率旁必须展示样本数、事件定义、来源、时间和风险；宽表只允许模块内部横向滚动。
- 页签需要支持点击、方向键、Home/End 和正确的焦点/ARIA 关联；桌面和 390px 手机都不得产生页面级横向溢出。

### 9.2 A 股变盘研究

当前第一版把变盘定义为：以决策时点冻结的 20 日高低区间为边界，加上 0.25 ATR 与 0.25% 价格下限，之后 5 个交易日第一次收盘越界决定向上或向下，否则记为不变盘。只使用每个历史决策点之前的数据计算压缩、区间位置、波动和量能；相似样本少于 20 个时不输出概率。

下一步准确性升级按以下顺序实施：

1. 使用当时可见的股票池和成分记录，消除当前股票池带来的生存者偏差。
2. 对重叠的 5 日标签使用 purged walk-forward 和 embargo，报告独立折的稳定性。
3. 增加 Beta/Wilson 置信区间、可靠性分层和概率校准曲线，不只展示点估计。
4. 在趋势、震荡、risk-off 和数据降级状态下分别统计基线，避免跨环境平均掩盖失效。
5. 加入停牌、涨跌停无法成交、A 股费用和滑点压力测试；只有多窗口稳定后才允许进入 shadow 订单意图。

### 9.3 港股独立研究域

当前港股只读模块读取 5 位代码的真实快照和前复权日线，展示 5/20/60 日收益、均线结构、波动率、20 日高点回撤、量能和过去相同趋势标签的未来 5 日上涨频率。规则分不是上涨概率，同趋势样本少于 20 个时概率保持空值。

港股不能直接复用 A 股交易规则。任何未来港股 paper 必须先建立港交所日历和时段、T+0、每手股数、港币和汇率、印花税与平台费用、公司行动、独立账户和组合风险预算。完成前只做观察和跨市场研究，不生成港股订单。

### 9.4 国内期货与跨市场策略上下文

当前第一版只读取受控的国内期货主连快照和主力连续日线，覆盖股指、贵金属、有色、黑色、能源化工和农产品。页面展示 5/20/60 日收益、波动、60 日高点回撤、成交量和持仓量，并结合真实全球指数输出风险基调、优先策略族、降权策略族和证据。

主连连续序列不代表可交易具体月份合约，也未建模换月、保证金、夜盘、交割和期货费用。下一阶段必须完成中国开盘前可见数据的时区对齐、状态连续确认、按市场状态分层的历史增量价值测试，再决定是否让跨市场上下文影响 shadow 权重；在此之前不读取期货账户、不生成期货订单，也不自动改变 A 股 paper 仓位。

### 9.5 代码与数据边界

- A 股变盘逻辑保持在独立 `turningPointScanner`，港股和期货归一化留在行情桥，港股研究、真实策略稳健性和跨市场组合分别留在独立服务模块。
- 新增或修改报告字段时同步更新桥接、Fastify、前端客户端和契约测试。
- 只保存有界日线、特征和验证摘要；不默认落盘无限 tick、全量网页正文或重复快照。
- 上游不可用时返回真实降级状态，不使用静态候选或模拟港股填充。
- 变盘和港股研究保持只读，不能绕过市场状态、组合风控和人工批准进入外部执行。

## 成效判断

系统进步不以“今天赚了多少”单独判断。每个版本至少应记录：

- 20/60/120 个交易日样本外收益和最大回撤。
- 不同市场状态下的交易数、胜率、盈亏比和盈利因子。
- 相对基线的增量收益、换手、成本和最差窗口。
- 数据降级次数、无效订单数、风控拦截数和审计完整率。
- 参数切换次数、策略退化次数、回滚次数和 shadow 到晋级比例。

只有在多段样本外和连续 paper 观察中保持稳定，才可以称为“有进步”；仍不能据此承诺未来收益。
