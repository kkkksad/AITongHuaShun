# 多市场Paper账户与事务账本目标设计

状态：目标设计，尚未激活。核对日期：2026-11-10（北京时间）。长期选择见[0047](../decisions/0047-multi-market-paper-ledger-migration.md)，本轮设计核验见[模块27](../plans/2026-11-10-multi-market-ledger-design.md)。

## 当前事实与缺口

主系统只有一个A股Paper账户：PAPER-CN-01，本金20000元；设计时空仓现金20000元是历史状态，11月10日收盘后为现金11722元、四持仓四成交单，当前资金以原账本为准。两个Store固定该身份，OrderRequest/OrderRecord/PositionSnapshot没有账户或市场路由；TradingSystem也只组装一套Store/Broker/Risk。JSON账户身份已按[0046](../decisions/0046-single-account-paper-ledger-binding.md)严格检查。这些事实不能解释为已经支持多个账户。

当前主账本是单进程JSON，不具备跨进程锁或数据库事务。既有SQLite是[只读长期归档](../operations/paper-history.md)，其有界摘要供网站读取；它不能完整捕捉两次轮询之间的所有事件，也不能用来重建任意历史账户或替代主账本。

期货现有16个主连的研究快照/连续日线，桥接研究缓存15分钟、Node读取缓存60秒。没有具体合约交易报价、合约规则目录、独立资金、保证金、开平仓撮合或结算。港股/数字资产同样只有研究能力。新闻、全球影响和玄学等模块没有账户或订单域。

## 账户、市场和资金不变量

每个交易账户须显式绑定accountId、marketId、currency和accountEpoch；每次重置生成新epoch，重启保持。目标首批市场标识为CN-A与CN-FUTURES，均为CNY；具体值需要在共享契约中统一后才能进入HTTP、数据库和调度。

现有A股账户原样保留，不能用创建期货账户的动作扣除、重置或重新解释其20000元。期货本金须单独配置，无默认自动资金划转。只读总览可按币种相加，跨币种总额须有明确汇率时间与来源，不能把不同币种直接相加。

| 对象 | 必需归属与约束 |
| --- | --- |
| 账户/世代 | accountId + epoch；绑定marketId/currency/规则版本，不允许客户端任意认领 |
| 标的 | marketId + exchange + instrumentId；具体合约不同到期月份是不同instrument，主连只读 |
| 订单、成交、持仓 | accountId + epoch + marketId + instrumentId；外键和路由同时核验，不能只靠symbol |
| 幂等请求 | accountId + epoch + clientOrderId；保存规范化请求摘要，同键不同请求明确冲突 |
| 资金流水、风险、检查点 | 同账户同世代；有序序列/可核对余额/已消费游标，不能消费其他账户结果 |
| 暂停/策略/重置 | 单账户控制修订；该账户旧异步计划失效，其他账户保持；全局紧急停止另设显式控制 |
| 结算、合约规则 | 交易所/交易日/具体合约/不可变规则版本；不能复用A股自然日期或T+1 |

相同clientOrderId在不同账户可以各自表示一项操作，但同账户同世代不能重复扣款；重试须返回已持久化结果。相同字符串代码在不同市场不能共用持仓或行情许可。共享的只读行情带完整身份和来源时间，不能携带账户执行权限。

路由按认证身份与账户白名单解析，错误账户、错误市场或不兼容旧客户端在写盘前拒绝。旧A股接口可作为明确的PAPER-CN-01兼容适配器，不能把未知账户参数静默丢弃后路由至A股。新增账户接口独立版本化，共享类型与OpenAPI同步。

## 单机事务账本方向

目标为单writer的事务SQLite，适合当前同机、低频Paper与独立账户需求；不是本轮已安装的新主账本。未来多writer、跨主机可用性或经实测超出其容量时，再评估PostgreSQL。现阶段不因CPU空闲额外加入Redis、消息队列或数据库常驻进程。

Node生产镜像当前是20-alpine，没有可直接使用的内置node:sqlite。驱动必须锁定版本并验证Windows开发机、Linux musl生产镜像、目标CPU/Node ABI、构建与重启恢复；也可另行升级Node后独立验收内置驱动。通过前不加入STORE_BACKEND=sqlite、不切换账户，不在行情桥内增加写账接口。

数据库位于独立私有数据目录，文件/目录权限受控、不开放公网数据库或任意SQL接口。启用外键、明确journal/synchronous政策和锁等待期限；目标WAL与FULL持久性还须以真实驱动的崩溃/磁盘实验确认。锁等待不得超过订单HTTP期限，无无限排队；满载或忙时以稳定错误返回，客户端使用原幂等键查询/重试。

目标表按职责拆分：accounts/account_epochs、instruments/instrument_rules、orders/fills/positions、cash_postings、risk_checkpoints、idempotency_requests、settlements、audit_events与migration_manifests。跨域表使用包含账户/世代/市场的复合外键与唯一约束，不能仅有独立account_id字符串。具体DDL随适配器实现提交，不在本设计中虚构已存在表。

一次接受订单与预约资金、一次成交及其资金流水/持仓/订单/风险消费检查点/审计，分别作为完整事务提交。数据库提交后才发布WebSocket/通知；若需要可靠重发，事务内保存有幂等标识的outbox。发通知失败不能回滚已经成交的资金；提交结果不明时先按幂等键查询，不另起新请求补单。

上游行情与研究读取在事务外完成，不能等待外网时持有数据库写锁；进入写事务后复核账户控制修订、交易日/时段、报价年龄、资金/保证金和风控版本。只读UI不推进风险或结算状态。引用同一只读行情不允许跳过逐笔核验。

资金数值方案须独立定义精度、乘数、舍入与溢出界限。旧JSON使用JavaScript浮点，不得导入时静默四舍五入改变余额/成本/盈亏。保留原始备份和逐字段数值，先报告无法无损转换的记录；单位化货币/价格需通过原费用模型和双向对账，未通过停止激活。

## 迁移、激活与恢复顺序

1. **离线预检。** 在私有副本解析版本、账户与epoch、字段类型/有限值、订单/成交/持仓身份、序列、冻结与风险游标。存在缺口输出具体错误，禁止自动清零、猜账户或按不完整历史重建全账。
2. **选择并验证驱动。** 实现相同TradingStore合同和独立事务测试；验证不同账户同键/同symbol、拒绝错误归属、失败回滚、锁超时、重启与恢复。不连接生产主账本。
3. **备份与冻结writer。** 进入明确维护状态，拒绝新增写请求，停止自动执行并等待已在途交易/通知边界完成；关闭唯一writer后复制原始JSON和私有配置，记录摘要、代码版本和账户世代。仅暂停策略但仍允许HTTP写入不构成冻结。
4. **导入候选库。** 在新的私有路径创建，使用一个导入事务；保留订单/持仓/完整周期/风险检查点/控制/计数与原始来源摘要。记录源SHA、schema和规则版本。重入只能验证同一源，源改变必须重新生成候选，不能追加成重复资金。
5. **双端只读对账。** 核对现金、冻结、初始权益、全部持仓成本/T+1、每张订单及策略、闭合结果/风险游标、epoch/序列和幂等效果。既有历史已裁剪的缺口如实保持，不伪造丢失成交。原始源保持静止且摘要一致。
6. **原子激活。** 数据库事务之外的运行配置也须有可恢复协议：持久化迁移manifest和唯一active-writer栅栏，核对候选库与最小兼容二进制后原子切换明确后端配置。启动只能选一个writer；旧进程不能继续写原JSON，禁止交易双写。注入每个中断点，重启必须选择唯一已验证状态。
7. **受控恢复。** 先只读确认资金/风险/身份和既有接口，再恢复单账户自动执行；后续有新交易必须以新库为权威。独立期货账户仍等待合约/撮合验收，不随数据库迁移自动开启。

激活前失败可关闭候选库并继续使用字节保持的原JSON。激活后若还没有新写入，可在确认writer已停止、源摘要/检查点一致后按manifest回退。**发生新订单、撤单、重置、成交或结算后，不得恢复旧JSON丢掉新状态。** 此时先停止新写入，使用兼容二进制修复新库，或执行完整、核对过的反向迁移；不能把代码镜像回滚等同于数据回滚。

备份使用SQLite在线备份/一致快照协议并核对完整性，不直接复制活动WAL库主文件。恢复演练在隔离路径且禁止第二writer连接生产；同盘备份与上一镜像只能解决部分逻辑故障，异机加密备份仍需单独实现。

## 期货账户的独立准入

只有下列条件全部通过，才创建可执行期货账户并开启Paper撮合：

- **具体合约与来源。** 有白名单内具体到期合约、交易所、品种与主连映射及有效期。连续主连用于研究，禁止直接作为可成交合约。拿不到合格具体合约报价就保持观察。
- **独立交易报价。** 具备供应商来源时间/接收时间/完成时间、量价单位和交易日，明确刷新/最大年龄/未来时间/缺失策略；15分钟研究缓存不能复用为即时成交许可。
- **版本化规则。** 有可追溯来源和生效区间的乘数、tick、手数、价格限制、初始/维持保证金、费用、平今/平昨与交割/到期限制。缺规则或冲突不猜默认值。
- **持仓和费用。** 多/空、开仓/平仓、今昨仓、资金与保证金冻结/释放、滑点、手续费及盈亏均专用计算。股票的100股整手、买卖含义和T+1不能直接复用。
- **日夜盘与结算。** 显式交易所日历和夜盘交易日映射、节假日/无夜盘、跨午夜、结算价与时间可见性；按交易日逐日盯市，重复结算幂等，修订价有明确更正事件。研究报价或昨收不能替代正式结算价。
- **风险与恢复。** 名义暴露/杠杆、保证金不足、跳空、涨跌停无法平仓、过期合约、数据失联和结算缺失均可复现。资金不足停止该账户新增，不能借用股票现金或隐藏未实现亏损。
- **策略验证。** 固定参数、具体合约和换月/费用的时间安全回放，检验趋势与区间等策略在不同状态的增量，报告闭合样本、净期望/回撤/成本，而非用主连历史胜率代替实际可实现收益。

取消A股固定现金预留不取消期货必要保证金，也不允许无限杠杆。账户单独暂停、限额、日损失、幂等和调度预算；总览展示同币种汇总时仍可追溯每个账户本金/权益/冻结/保证金与数据时间。

## 必须通过的业务故障矩阵

| 场景 | 验收结果 |
| --- | --- |
| 两账户使用相同clientOrderId | 各自独立一次；同账户重试不重复扣款，同键不同请求冲突 |
| 账户/市场/具体合约路由传错 | 写盘前拒绝，两个账户余额/持仓/风险都不变 |
| 同时成交、撤单与冻结释放 | 单事务顺序有唯一结果，无负可用资金或双释放 |
| 暂停/重置发生在研究或通知等待中 | 仅原账户旧轮失效，已提交成交保留，另一账户继续 |
| 磁盘满、锁超时、提交失败/结果不明 | 未提交状态全部回滚；已提交按原幂等键查询，不自动新建账户或补单 |
| 激活各阶段进程崩溃或旧二进制重启 | 唯一writer与权威账本可判定，无JSON/SQLite双写 |
| 新交易后发布/恢复旧代码 | 不回退旧资金快照；不兼容二进制拒绝启动写入 |
| 夜盘跨日、节假日、重复或修订结算 | 使用正确交易日，幂等且可核对更正，其他账户不受影响 |
| 股票行情正常、期货源故障 | 期货新增受限，股票不因无关接口失败停止；共享宿主仍有总资源上限 |

## 资源使用与实施门槛

现有4核/约3.7GiB服务器应以端到端延迟、有效任务完成数、队列上限、错误恢复和资金一致性评估，不以CPU/RAM满载为目标。UTC22:46休市样本约2.3GiB可用内存、6.2GiB磁盘不能证明盘中容量。

先保留独立股票/指数快通道、历史2工作槽/24接纳上限、Node实际研究读取64预算和每实例8计算预算。新市场须划分预算并做隔离并发测试，不能直接倍增所有任务。CPU密集回测若经测量影响事件循环，再评估受限worker；行情与资金事务不能等待批量研究。

实施依次拆成：驱动/事务存储与故障测试 → 离线迁移/激活工具 → 账户白名单路由/界面 → 具体期货报价与规则 → 独立撮合/保证金 → 日历/结算/恢复 → 固定策略回放/有限Paper观察。每阶段通过后独立发布，主账户原样保留；本设计完成不表示这些阶段已经实现。
