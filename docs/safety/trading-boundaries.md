# 交易与数据安全边界

## 默认运行模式

项目默认是研究和模拟交易环境。任何行情、资金流、新闻、账户和订单数据都必须明确标注来源及其真实性。

## 数据边界

- 模拟数据必须在界面和文档中显式标注。
- 真实数据必须记录供应商、授权范围、时间戳、时区和更新频率。
- 使用真实或延迟行情不代表获得账户或下单权限；行情提供者必须保持只读。
- 新闻数据必须保留原始来源、发布时间、抓取时间和去重依据。
- 回测不得使用决策时点之后才发布的数据。
- 缺失、停牌、涨跌停和复权规则必须显式处理。

## 回测边界

- 样本内、样本外、滚动验证和模拟盘结果不得混为一谈。
- 交易成本、滑点和成交限制必须进入计算或明确声明未建模。
- 随机过程必须固定种子并记录配置。
- 指标实现发生变化时，需要增加回归测试并更新决策记录。

## 订单边界

行情读取与订单执行必须拆分为不同权限域。

任何未来的下单能力至少需要：

- 账户白名单。
- 单笔和累计额度限制。
- 仓位、价格和市场状态风险检查。
- 幂等键和重复订单保护。
- 不可篡改或可追溯的审计日志。
- 逐笔人工批准。
- 紧急暂停和撤销机制。

未经审计的第三方自动交易服务不得直接连接真实券商账户。

当前 `MockBrokerAdapter` 只允许 `paper` 或 `sandbox` 语义，并在 `live` 环境下立即失败。它必须委托 `PaperBroker` 执行风控和撮合，不得维护第二套费用、幂等、账户或订单逻辑。

当前 AkShare 桥接只暴露健康检查和行情读取接口，不包含账户、持仓、下单或撤单能力。`MARKET_DATA_PROVIDER=akshare` 必须与 `MARKET_MODE=paper` 配合，订单继续由本地 `PaperBroker` 执行。

外部券商凭据只能通过服务端密钥引用加载。禁止把明文 Token 写入源码、提交记录、浏览器存储或任何 `VITE_*` 环境变量。

## 智能体权限

- 智能体可以协助研究、生成候选、运行回测和整理报告。
- 智能体不得自行扩大数据或账户权限。
- 智能体不得把研究建议解释为授权下单。
- 涉及真实资金的动作必须由独立风控层和人类明确批准。
